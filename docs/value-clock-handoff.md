# 全站基建价值时钟 Handoff

状态：价值时钟已实现，V2 保持隐藏入口，通过 `/v2?section=value-clock` 直达。后台“公开工具 → 基建价值大屏”（`base_value_dashboard`）默认关闭，依赖 `site`、`tools`、`v2`。其余三个大屏仍为待实现方案，不提供未实现页面的跳转。

本页回答：**本站保存的基建排班，随着时间累计预计能产出多少价值？**

四页沿用同一套自动统计账本：

- [优化增益时钟](optimization-gain-clock-handoff.md)：与同条件原排班比较。
- [全站基建工厂](production-factory-handoff.md)：将资源产出画成生产流水线。
- [围观价值窗口](value-window-handoff.md)：计算本次观察期间新增的产出。

## 1. 页面与使用方式

访客可以直接查看累计等效理智、每分钟预计产出、今日累计、当前统计账号数，以及龙门币净收入、作战经验点数、合成玉。本站保存的历史排班和后续排班自动纳入统计。

直达地址独立懒加载大屏，不装载工作台侧栏、登录会话或个人排班流程，也不新增依赖。背景沿用 [设计规范](../design.md) 的雾纸与深色主题，铜金渐变的累计数字为视觉中心，主文案为“博士歇会儿，基建还在打工。”。累计主读数在桌面和手机上均展示完整数值，按字符数适配字号；整数为视觉中心，两位小数缩小并降低对比度，今日累计的大数保留万／亿单位。参考 Tesla 网页设计分析中的克制字重、正常字距和短过渡，保留本站铜金配色；该参考并非车机动效规范。整数使用等宽固定列，仅在数字改变时进行约 220 毫秒、3% 字高的轻微淡入过渡，不叠加旧字形；小数保持静态排版，不逐位翻滚。主读数、资源与今日统计每秒最多更新一次。资源读数采用开放的对齐区域，状态文字保留完整宽度，空间不足时按钮换行。

Vite 本地开发默认使用独立的 905 账号预览：累计约 2882 万等效理智，每分钟 206.40 理智，并显示“本地预览”标记。页面按钮可切换到真实统计（`clock_data=live`）；预览数据仅在浏览器内生成，不写入数据库，生产构建只读取真实 API。预览查询使用单独的 `['public', 'value-clock', 'preview', null, null]` 缓存键，刷新不会重复增加时间。

统计口径、历史起点和更新时间放入展开说明。统计表示网站方案的预计产出。统计起点取数据库中最早可用的历史结果，首次发布即包含可构造的历史累计。

全屏由点击触发；浏览器不支持或拒绝时启用展示布局，保留退出按钮。Escape 退出后焦点回到触发按钮。支持暂停动态显示，暂停不改变服务器累计；减少动态效果时每秒最多更新一次，正常情况下每 250 毫秒最多更新一次。连续数字不设置 `aria-live`，状态变化才播报。

路由为 `/v2?section=value-clock`，不添加 V2 导航、工具目录或历史详情跳转。后续三个 section 分别为 `optimization-gain-clock`、`production-factory`、`value-window`；全部完成并获准开放入口后再增加四页导航。

总开关控制页面和公开读取；关闭后保留账本及自动同步所需的变更记录，再开放时读取同一统计系列。

## 2. 自动统计来源与历史构造

来源为 `optimization_result_history` 中服务端保存的完整结果，包括生成结果、手动方案和已归档结果。免费预览按服务端完整产出读取，前端权限投影不影响统计。

### 时间与去重

1. 已绑定档案使用现有游戏 UID 去重；未绑定档案按档案 ID 独立统计。渠道显示名称不参与身份拼接。
2. 同一统计身份的所有历史结果按保存时间排序，同一时刻以保存顺序确定最后一份方案。
3. 每份可用结果从其保存时间开始，持续至下一份结果保存时间或可证明的库存截止，以较早者为准；最新方案在库存允许的范围内继续估算。
4. 每个身份同时仅存在一份当前速率，重复生成和多个档案不会叠加。同一方案在同一时刻的重复保存不产生额外累计。
5. 最新结果明确无效或缺少产出时，之前的区间在该次保存时间结束；缺失段不以旧方案补算。
6. 归档和重命名保留原时间与数值；删除结果或档案、绑定变化、档案合并后，按剩余历史重新校正对应身份的区间与汇总。

统计是基于现存网站结果的连续运行模型。已从数据库删除的历史无法恢复，历史上实际切换方案或游戏执行时刻也不作为已知事实。

### 旧格式与缺失值

- 复用现有 `calculateProductionSanity` 和 `getProductionSanityLedger`。输入周期 `hours` 必须为有限正数，产出、消耗及支持房间向量先按 `24 / hours` 折算；已经归一化为 24 小时的结果保持不变。
- 旧结果缺少后续新增的心情验证字段时，使用其已有生产账本。明确心情无效、循环不稳定、缺少可执行房间或必需产出向量的结果不构造收益区间。
- 数值必须有限；明确 0 是有效数据，缺失信息不填成虚假的零产出。可选支持房间缺失沿用原估值语义。
- 缺少合成玉供应分析或库存支撑的结果不推定可永久持续。

### 有限库存

复用 `orundum_economy` 与 `intermediate_depletion`，并核对赤金、碎片及负龙门币净额的库存支撑。区间不能跨越已知库存耗尽时间。

相同库存数值与已知导入时间构成同一快照。首次历史结果固定该快照的时间锚点，后续方案保留或缩短截止时间；重复保存不补回消耗。当前绑定的导入时间晚于某份历史结果时，不把后来导入的库存套用于旧结果。缺少历史库存更新记录时采用同一快照的保守截止。

## 3. 共享资源口径

| 字段 | 单位与来源 |
| --- | --- |
| `sanity` | 统一净等效理智，包含支持房间和回收价值 |
| `lmd_received` / `lmd_spent` / `lmd_net` | 受供应约束的贸易龙门币、生产支出及差额 |
| `experience_points` | 制造作战记录 × 1000，展示为经验点数 |
| `orundum` | 受碎片供应约束后的合成玉 |
| `gold_produced` / `gold_consumed` | 赤金制造与消耗 |
| `shards_produced` / `shards_consumed` | 源石碎片制造与消耗 |

先取受供应约束的账本，再取展示值；赤金生产及其出售所得不能重复加为价值。三个主资源读数不是总价值的完整拆分。净额保留负值，积分使用未舍入数值，展示时才舍入。

对于每日向量 `Dk`、区间起点 `sk`、终点 `ek`，使用：

```text
累计(t) = Σ Dk × max(0, min(t, ek) - sk) / 86,400 秒
当前速度(t) = Σ 当前有效区间 Dk / 86,400 秒
今日累计(t) = 累计(t) - 累计(北京时间当天 00:00)
```

最新且不受库存限制的区间为开放区间。今日按 `Asia/Shanghai`，午夜只重置今日值，总累计继续。重启、刷新和多标签页不改变服务端账本。

同口径修正增加 `revision`。不兼容的估值改动使用新 `series_id` 与 `metric_version`，不能静默相加不同系列。其余三个页面沿用同一向量及时间口径。

## 4. 持久化、迁移与同步

实现位于 [来源校验](../server/value-clock-production.ts)、[历史同步](../server/storage/value-clock-sync.ts)、[数据库结构](../server/storage/value-clock-schema.ts) 和 [公开快照](../server/storage/value-clock-store.ts)。

数据库迁移版本为 `2026-11-22.3`，遵循项目[数据库迁移流程](database-migration.md)，在迁移完成前将已有历史构造成数值区间与每日汇总，失败则不标记迁移成功。保留原结果及旧迁移账本。

- `value_clock_series` 保存统计起点和修订版本。
- `value_clock_pending` 保存结果及档案变动所影响的身份。数据库触发器同时覆盖 API、Worker 保存及合并路径。
- `value_clock_intervals` 保存去重后的来源、时间与冻结数值，使用 `NUMERIC`。
- 有限区间按北京时间拆入 `value_clock_days`，通过触发器维护 `value_clock_daily_totals`。
- 开放区间每个身份最多一份，读取时计算从其起点到当前时刻的累计；不为无期限区间预建未来日期。
- 公开刷新只处理待同步身份；事务内校正区间和汇总，再读取同一时间锚点。没有来源变更时不重新扫描历史结果 JSON，也不每秒写库。
- 同进程合并并发公开读取，同步事务使用数据库锁防止多进程重复构造。处理期间发生的新保存会留下新的变更记录，下一次读取继续同步。

## 5. 公开 API 与浏览器时间契约

当前接口为 `GET /api/site/value-clock?view=production`，匿名可读，返回 `Cache-Control: no-store`。仅支持生产视图。服务端聚合数值，页面读取快照。

| 字段 | 约定 |
| --- | --- |
| `schema_version` | 当前为 1 |
| `view` | `production` |
| `series_id` / `metric_version` / `revision` | 统计系列、估值口径和数值修订 |
| `tracking_started_at` | 最早可用历史区间起点，无可用记录时为 `null` |
| `server_now` / `as_of` | 服务端响应时间及读数锚点，UTC ISO 时间 |
| `valid_until` | 本快照可向前估算的截止 |
| `day_started_at` / `day_ends_at` | 北京时间当日边界 |
| `totals` / `today_totals` / `rates_per_second` | 累计、今日和每秒速率向量 |
| `active_accounts` | 当前有效的去重统计身份数 |
| `status` | `not_started`、`ready`、`empty`、`paused`、`rebuilding` |

没有可用历史时向量为 `null`；有历史但当前库存已耗尽时保留累计并返回零速率。真实累计 0 正常展示。

`valid_until` 最迟为锚点后 120 秒、最近库存／区间截止和北京时间午夜的最早者。浏览器每 30 秒刷新，回到前台或重新联网时刷新；隐藏时暂停轮询与绘制。使用单调时间投影真实数值，再按展示频率刷新；短过渡只作用于数字字形，不改变产出速度与账本。系统时间变化不能增加累计；暂停、页面隐藏或超过有效期时停止更新动画，失败保留最近有效读数并提供重试。减少动态效果模式每秒更新静态读数。

公开查询键为 `['public', 'value-clock', 'production', null, null]`。API 边界校验结构并传递查询 `signal`。向下修正直接校准并提示“统计已校准”，不取历史最大值掩盖修正。

增益、指定观察起点以及个人贡献读取按其余三份 Handoff 后续实现，不在当前页面添加占位链接或操作。

## 6. 验收

- 实际迁移前已存在的历史结果可构成累计，超过 7 天的旧历史正常计入；迁移重跑不重复累计。
- 固定每日价值 864 的方案，100 秒累计 1；下一份结果按保存时间切换，同一 UID 多档案不叠加。
- 未绑定档案、归档结果、旧周期归一化、明确零产出、负净额、库存耗尽和无效结果均有回归。
- 新结果、改名、归档、删除、绑定及合并变更可以校正汇总；午夜只清今日，重启继续读出同一历史。
- 真实浏览器覆盖 320、375、414、768、1280、1920px、深色、200% 字号、减少动态效果、暂停、全屏及降级、断网冻结、恢复和校准。查看实际截图并确认无横向溢出、金额断裂和单位截断。
- 运行[项目验证规范](agent-validation.md)要求的针对测试、完整 PostgreSQL 回归、构建、迁移验证、API／公开导出、文案和两项强制检查。
