# 前端查询缓存

TanStack Query v5 当前管理库存、库存余额提示、新手任务和优化任务列表，以及后台用户分页列表。`App` 的 `QueryProvider` 为各路由共享一个内存中的 `QueryClient`，不持久化缓存。请求继续使用 `apiJson`、`adminApiJson` 和现有优化 API 函数，沿用超时、错误消息、诊断及管理员会话过期处理。

## 状态归属

查询保存服务端数据、加载状态、错误和分页游标。组件保留筛选输入、选择、弹窗、通知和提交状态。不要把查询返回的数据再复制到 `useState`，也不要为同一个查询另设请求序号或取消控制器；查询函数应把 TanStack Query 提供的 `signal` 传给请求函数。

默认新鲜期为 30 秒，关闭自动重试和窗口聚焦刷新。库存通过下述失效桥接刷新；任务中心单独启用回到前台时刷新和定时查询。失败后保留同一身份下最后成功的数据，并显示错误。切换身份或分页时不使用上一查询的数据作为占位。

## 查询键与清理

| 数据 | 查询键 |
| --- | --- |
| 库存（页面与余额提示共用） | `['user', userId, profileId, 'inventory']` |
| 新手任务 | `['user', userId, profileId, 'onboarding-tasks']` |
| 优化任务分页 | `['user', userId, profileId, 'optimization-jobs']` |
| 后台用户分页 | `['admin', adminUsername, 'users', capabilities, operationsSearch, page, pageSize, search, filters]` |

没有活动档案时使用 `null`；没有已确认的用户身份时禁用用户查询。后台用户列表按管理员会话、权限和完整筛选条件隔离，不属于某个游戏档案；无访问权限或离开用户页时使用禁用查询并脱离原查询，取消无人订阅的请求。

`useToolSession` 应用会话响应时删除其他用户的查询；退出账号删除全部用户查询并取消在途请求。账号安全页的退出和注销申请成功后同样清理。后台退出或会话失效由 `resetAdminState` 删除后台查询。用户会话与管理员会话分别清理。

## 刷新与修改

- `markInventoryStale()` 仍是道具使用、领取和其他库存变化的通知入口。`QueryProvider` 通过现有 `useInventoryRefresh` 将通知转换为库存和新手任务查询失效，回到前台时也刷新。请求中收到的失效通知在请求结束后补刷，多个消费者共享同一请求。
- 优化任务使用 `useInfiniteQuery`，打开任务中心或有进行中任务时每 10 秒刷新，否则每 30 秒刷新。页面隐藏时暂停轮询，回到前台时刷新。现有跨标签页任务通知仍合并为延迟 250 毫秒的刷新；慢请求不会被定时查询反复取消。刷新已加载的多页时依次读取新的游标，合并结果时按任务 ID 去重。
- 取消任务仍执行原有确认与提交，成功后使对应用户、档案的任务列表失效。
- 后台用户修改成功后调用 `loadUsersPage`，使当前管理员的所有用户列表查询失效：当前页刷新，其他缓存页再次打开时读取新数据。保留操作原因、乐观并发检查，以及“操作成功但刷新失败”的错误处理。

## 本阶段保留的流程

会话与工作区读取、自动保存、计费报价与提交、任务提交、余额账单和森空岛快照客户端仍使用原有流程。自动保存的串行队列与草稿恢复、提交的幂等键，以及森空岛的请求合并、版本失效和跨标签页通知不由查询缓存替代。后续迁移应逐个明确数据身份和失效来源，保留这些流程已有的边界语义。

涉及缓存共享、身份切换、迟到响应、退出清理或修改后的失效时，运行 `inventory-query.test.tsx`、`inventory-hooks.test.tsx`、`useOptimizationTaskCenter.test.tsx`、`useAdminUserList.test.tsx` 及相关页面集成测试，再按 [验证规则](agent-validation.md) 运行仓库检查。
