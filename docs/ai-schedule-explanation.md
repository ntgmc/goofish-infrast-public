# AI 排班解读

V2 结果页支持按需生成当前排班的中文解读，帮助用户判断应先关注的库存问题、培养建议的收益与投入，以及下一步操作。公开示例采用随页面提供的示例说明，不调用模型；个人结果只在用户点击后调用。同一报告、可见摘要及解读版本复用已保存的解读。首版不提供自由聊天、自动重新排班或额外次数购买。

结果页的角色头像与“排班解读”提示打开浮动对话框，可边看排班边阅读。头像和窗口作为一组移动：收起时拖动头像，展开时拖动头像或标题栏；聚焦头像或标题栏后也可用方向键调整位置，整组会保持在可见工作区内，避开桌面左侧导航栏。关闭或按 Esc 收起窗口后，头像的位置和生成状态仍保留；切换账号、档案或报告后重新打开对应解读。手机上正文独立滚动。

打开窗口和重新查看只读取状态；需点击“解读这份排班”才发起模型调用并按现有额度计次。生成中收起后可重新打开继续查看。

## 解读依据

解读用两至三个短段给出判断和依据，只引用与决策有关的少量数字。服务端补充已有报告中的库存覆盖天数、培养总成本与材料缺口、单项收益占当前产出的比例，以及可用的默认 MAA 模拟对比，计算后再交给模型组织语言。

每条培养建议都是相对当前排班独立测算，不能将多条收益相加，也不能据此认定现有材料足够同时完成多条建议。成本完整且没有材料缺口时，现有库存可覆盖该单项培养；补齐材料的回本天数和按全部培养投入计算的回本天数分别传入。成本不完整时不作材料齐备或回本结论。建议完成一项培养后重新排班，再评估其余建议；建议计算完成状态不代表用户已完成培养。

库存净变化为负时，结合已有库存覆盖天数说明补货时机。没有低库存告警不能当作库存充足或长期平衡的证据；缺少库存时只建议核对，不推算耗尽时间。默认 MAA 对比来自同一报告中的模拟，不作为上次排班或其他布局的对比。

## 管理后台配置

拥有 `admin_manage` 能力的管理员可打开 **站点管理 → AI 服务**（`/admin/ai`）。所有业务配置保存在数据库中，保存后用于新请求，无需修改环境变量、重启服务或重新构建前端。功能默认关闭。

1. 填写用户可见的实际服务商名称、API 协议、HTTPS 根地址、模型名及专用 API 密钥。
2. 按服务商人民币报价填写每百万普通输入、输出、缓存命中的 token 价格。Anthropic 支持分别配置 5 分钟和 1 小时缓存写入价格；缓存单价允许为零，留空表示未配置。设置费用上限和账号额度。
3. 打开“开放 AI 排班解读”，填写修改原因后保存。这个开关与 **功能开关 → 排班 → AI 排班解读** 使用同一份设置；账号档案、登录、V2 等上级功能也必须开放。

配置不完整或最大预留超过单次费用上限时不能开启。管理员可以关闭功能并保存未完成的配置。关闭后停止新生成，已有解读继续可读。

| API 协议 | 根地址示例 | 自动追加路径 |
| --- | --- | --- |
| OpenAI Chat Completions | `https://api.openai.com/v1` | `/chat/completions` |
| OpenAI Responses | `https://api.openai.com/v1` | `/responses` |
| Anthropic Messages | `https://api.anthropic.com/v1` | `/messages` |

兼容服务使用其自己的根地址。地址不能包含账号、密码、查询参数或片段。Chat 模型须支持 `max_tokens`，Responses 使用 `max_output_tokens` 并指定 `store: false`，Messages 使用 `max_tokens`、`x-api-key` 和 `anthropic-version: 2023-06-01`。仅接入文本消息与 token 计价，不执行工具。

密钥采用 AES-256-GCM 加密存储。管理接口和页面只返回“已配置”状态，不回传明文或密文；修改时留空保留原密钥，可以主动更换或删除。修改需要当前设置及功能开关的版本号，发生冲突返回 409。配置修改与不含密钥的操作审计在同一事务内提交。

加密使用现有服务器 `MAA_ADMIN_SECRET` 派生的独立用途密钥；轮换期间支持 `MAA_ADMIN_SECRET_PREVIOUS`。这是服务器基础密钥，不能在后台显示或编辑。退役旧密钥前，应在后台重新保存 AI 密钥，使其使用新密钥加密。

## 计价、额度与限制

| 后台配置 | 默认值 |
| --- | --- |
| 免费账号累计成功次数 | 3 次 |
| 有效维护卡账号每月成功次数 | 10 次 |
| 每账号每日实际模型请求上限 | 20 次 |
| 每账号同时生成上限 | 1 份 |
| 单次费用上限 | 0.05 元 |
| 全站每日 / 每月预算 | 10 / 200 元 |
| 输入 / 输出 token 上限 | 8000 / 800 |
| 请求超时 | 45000 毫秒，可配置 1000–90000 |

价格与模型须由管理员填写，默认空配置不能发起调用。价格须覆盖供应商实际收费规则及人民币换算；不支持额外工具费、多模态、自动代理或未计入输出上限的推理费用。先以供应商账单核对真实价格和用量，再开放服务。模型或价格调整时同步修改配置。服务商侧消费限额可作为独立账单保护。

日/月边界均采用北京时间，月度赠送不累计。账号只要有一份授权有效的 CDK 档案即可使用月度额度，所有档案共用；临时免费体验、按次计费档案使用累计试用次数。维护卡失效后使用账号原有的剩余试用额度。后台调整额度后，仍统计当前周期内已成功和进行中的次数，不重置用量。

服务端按当前协议中最高的已配置输入单价及输入上限，加输出单价和输出上限预留费用；Anthropic 的缓存写入单价也参与最高价检查。发送前确认提示词和摘要的 UTF-8 字节数加消息开销不超过输入预留，仅支持这项保守估算适用的文本模型。费用以整数百万分之一元存储，按各项用量乘单价后合计向上取整，不自动重试。

调用前在 PostgreSQL 事务中串行检查用户额度、并发、每日请求数及全站日/月费用，并预留单次最高费用。重复点击同一报告读取进行中状态；GET 和前端轮询不会生成。预算统计包括所有成功、失败和进行中请求；已知用量按实际 token 结算，缺少用量、超时、网络失败等情况保留完整预留。

失败或输出截断不扣用户次数，已经发生的供应商费用仍计入预算。进程中断后，超过两分钟的进行中请求释放用户次数、保留费用，下次主动请求可重试。网络调用期间不持有数据库事务。生成成功但客户端断网时，后续读取可找回解读。

达到用户额度或全站预算后暂停新生成，已有解读仍可读取。赠送次数属于可配置的试运营额度，尚未作为固定商品权益加入维护卡目录。

## 后台调用记录

**AI 服务 → 用量与记录** 默认展示最近 30 天，可按时间、状态、账号 ID、服务商、模型筛选并分页。单次时间范围最多 366 天。查询包含相同筛选范围下的总调用数、成功/失败/进行中数量、已记录输入/输出及缓存 token、费用分类、已核算的各类 token 费用，以及每日和服务商/模型统计表；不是只汇总当前页。输入表单使用设备时区，每日统计按北京时间分组。

点击记录详情可查看档案与报告标识、调用耗时、服务商请求 ID、当次单价、token 与费用拆分，以及仍保存的成功解读。权限沿用 AI 配置的 `admin_manage`，对应接口为 `GET /api/admin/ai-usage`，详情使用 `?id=…`。站内读取、轮询或复用已保存解读不创建模型调用记录，也没有新的 token 消耗。

- OpenAI Chat 读取 `usage.prompt_tokens_details.cached_tokens`，Responses 读取 `usage.input_tokens_details.cached_tokens`。二者的输入总量已经包含命中的缓存 token，普通输入为总输入减缓存命中，不重复计费。
- Anthropic 的 `input_tokens` 只表示普通输入。记录将其与 `cache_read_input_tokens` 和 `cache_creation_input_tokens` 相加作为总输入；缓存写入通过 `cache_creation.ephemeral_5m_input_tokens`、`ephemeral_1h_input_tokens` 分别核算。只记录服务商实际返回的缓存使用情况，是否命中及适用价格由服务商决定。
- 每次开始调用保存当时的服务商、协议、模型和单价快照；修改后台设置不重算历史费用。费用拆分以百万分之一元表示，合计向上取整。
- 返回完整用量且相关单价齐全时标为“按用量核算”。OpenAI 未返回缓存明细且已配缓存单价不高于普通输入时，按全部输入使用普通单价估算，并标明“按普通输入估算”；已配缓存单价更高时保留预留。缺少总用量、实际使用的缓存类型价格或缓存写入时长时，保留费用预留及已有的 token 明细。
- 超时或未知服务商费用保留预留；回答被截断时仍记录已有 token 与相应费用，并退还用户次数。输入校验在发出请求前失败时记录零费用。
- 历史记录没有 token 或单价快照时保留原费用，并标为“历史费用，明细缺失”。汇总同时返回具有 token 记录和缓存明细的请求数，避免把缺失数据当作零。各类 token 费用只汇总已有核算明细；没有可核算明细时显示未记录。普通输入费用不混入缓存明细缺失时的估算额。核算结果用于站内预算管理，需与供应商账单核对。

后台没有复制提示词、原始报告、密钥或服务商原始错误。解读正文从已有保存记录按需读取；报告被删除后正文不可读，用量费用仍保留。档案、报告和账号被删除后清除对应关联标识，保留匿名用量和费用。

## 数据与权限

`GET /api/user/schedule-explanation?profile_id=…&result_id=…` 读取解读、额度和可用性；`POST /api/user/schedule-explanation` 仅接受这两个 ID 并主动生成。请求沿用登录、同源、功能开关和请求大小校验。服务端验证档案归属、授权及历史结果，再按当前能力投影；客户端不能指定提示词、模型或 token 限制。管理配置接口为 `GET/PUT /api/admin/ai-settings`，响应不缓存。

发送给模型的摘要包含布局、班次、预计产出、心情有效性、相关中间产物库存及覆盖天数、已有的默认 MAA 模拟差值，以及最多三条当前可见培养建议的收益、完整成本和材料缺口。邮箱、游戏 UID、CDK、森空岛凭据、报告标题备注、完整干员与原始计算数据不进入提示词。生成按钮显示实际服务商和传输范围。输出以纯文本显示，不解析 HTML、Markdown 或外部链接。

缓存键包含用户、档案、报告、可见摘要及解读规则版本。规则更新使缓存失效后，须由用户再次点击生成，按当前额度计次；不会自动重写旧解读或自动调用模型。权限变化不会复用包含隐藏数据的旧解读。`ai_schedule_explanations` 随结果、档案或账号删除；`ai_schedule_usage` 不存输入和输出，账号删除后清除外键关联，保留匿名 token 用量、当次单价与费用统计。个人数据导出包含已保存解读与本账号的使用状态，不含内部费用和缓存标识。`ai_settings` 是站点配置，不属于个人数据。

## 部署与验证

先应用 schema 版本 `2026-11-17.3`，再启动新 API。历史迁移校验值保持不变。部署后在后台完成配置，再打开功能开关。

```sh
pnpm test server/ai-usage-accounting.test.ts server/schedule-explanation.test.ts server/handlers/user-schedule-explanation.test.ts server/handlers/admin-ai-settings.test.ts server/handlers/admin-ai-usage.test.ts src/pages/admin/ai/AiSettingsSection.test.tsx src/pages/admin/ai/AiUsageSection.test.tsx src/pages/v2/ScheduleExplanation.test.tsx
pnpm run test:postgres server/storage/ai-settings-store.postgres.test.ts server/storage/schedule-explanation-store.postgres.test.ts
```

发布前按[验证规范](agent-validation.md)完成 API、前后端构建、PostgreSQL、迁移、架构及 dead-code 检查。真实供应商计费和回答质量在配置完成后用受控样本核验。
