# 养成规划

## 入口与数据

| V2 section | 用途 | 条件 |
| --- | --- | --- |
| `cultivation` | 根据 PRTS 作业或一图流统计推荐干员练度 | 已绑定森空岛的可用档案，包括免费档案；开启 `tools`、`skland` 及练度推荐 |
| `cultivation-projects` | 自选目标、材料缺口、合成与资源准备日期 | 独立的养成项目开关；使用当前档案已拥有干员 |
| `training-ratio` | 培养目标的钱书缺口与准备时间 | 账号模式使用绑定档案；手动模式无需登录 |
| `material-demand` | 新增养成内容的材料需求趋势 | 无需登录；开启 V2、公开工具中心及材料需求趋势 |

入口使用 `/v2?section=<section>`。旧地址 `/tools/cultivation-plan`、
`/tools/training-ratio` 保持可用。个人练度与库存统一读取[森空岛共享快照](skland-data-cache.md)：
进入页面自动读取，刷新统一更新；修改目标或筛选使用当前快照重算，不重复拉取个人数据。
库存不写入浏览器持久化存储；本地只保存目标、偏好或手动填写的草稿。

## 作业练度推荐

推荐对比精英阶段、等级、技能、所选专精、模组类型和潜能。作业模组不推断等级，
`moduleLevel` 为 `null`；未注明练度只补技能解锁条件（技能 2 精一、技能 3 精二）。
缺失资料保持未知，潜能需要信物或重复干员，不能通过材料规划补齐。

默认推荐 4–6 星，可选 1–3 星、全部或单一星级。修改依据、人数或筛选后点击
“更新推荐”才应用，编辑期间保留原结果；暂不培养／重新纳入直接更新。
结果可逐条或批量加入养成项目，材料与日历统一在那里计算。代表作业链接为
`https://prts.plus/?op=<id>`。同一干员字段以养成接口返回的最新数据为准。

### 证据与排序

- 只统计公开可用作业。按关卡、难度、动作、位置和朝向分组，再与簇首阵容比较，
  Dice 相似度达到 0.85 视为同一打法；缺少动作时按相同阵容保守合并。
- 同版本保留评价最多的来源，同票取较小 ID，不累计副本流量；簇内不同练度或
  执行条件仍保留各自反馈并平分簇预算。发布时间取最早首次发布，编辑不刷新年龄。
- 质量采用点赞／差评的 Wilson 95% 区间，上界低于 0.6 排除；有评价取下界，
  无评价默认排除，开启待观察后权重为 0.05。未来发布时间按年龄零处理。

```text
基础权重 = 质量 × (0.25 + 0.75 × min(发布天数 / 3, 1)) × 2^(-发布天数 / 180)
           × 曝光修正 / 簇内版本数 / 关卡内独立打法数
```

曝光修正以同关卡、同年龄段（7/30/180 天）的对数浏览量中位数为基准，限于
0.9–1.1，不使用 `hot_score`。常驻／其他内容预算为 0.3／0.7，只有一种时用完整预算。
好评不能解释为通关概率，低质量内容也不能靠归一化提高质量。

默认近期窗口为 180 天。“近期通用”可纳入历史常驻需求，但要求干员近期至少有
两个关卡、三个独立打法，每簇取一份评价后的 Wilson 下界至少 0.5；指定关卡或活动时一个可靠打法即可。
常驻模式要求窗口内常驻打法，历史模式可选全部时间。缺少评价时间或活动状态时保留未知，
不根据同步日期推断，也不因近期没有数据断言干员失去用途。

基础／实用／高覆盖分别覆盖分支内 60%／80%／90% 的有效需求，默认实用档。
精英化、等级、技能及模组类型联合计算，保留不能继续降低的合法目标；不可比较的目标并列。
显示各维度来源完整度，无法映射旧模组时仅缺失模组维度。

固定位置计一份需求；k 人替代组每人计 1/k，未知成员的份额不转给他人。
同作业同干员取最大份额。已满足任一备选时不推荐该组；选择一个备选后扣除同组需求。
排序使用未满足的相关需求权重 × `(1 + 养成参考分)`，同分比较原需求和候选键，
每名干员只选一个目标。展示用的作业参考分为需求权重 × 100。
库存、价格和刷取来源不参与排序；单名干员需求不能证明整份作业已可通关。

`POST /api/cultivation-plan` 在 `profile_id` 外接受 `recommendation`：
`scope`、`days`、`coverage`、`stageId`、`activity`、`category`、`profession`、
`rarity`、`rarityGroup`、`search`、`includeClosed`、`includeAlternatives`、`includeUncertain`。
响应包含查询口径、关卡目录、独立打法数及候选 `evidence`。
`rarityGroup` 为 `high`（默认）、`low`、`all`；`rarity: 1..6` 优先于分组。
筛选保存在 URL 的 `cultivation_*` 参数，活动／关卡搜索每次最多展示 50 项。

### 一图流统计与道具

统计来自 `https://auth.yituliu.cn/open/ak-operator-statistics/result`。
精二、专精和模组比例均以干员持有人数 `own` 为分母，目标比例指达到或超过该等级。
共同养成参考分为：

```text
30% × 精二率 + 50% × 最高单技能专三率 + 20% × 最佳模组养成比例
单模组养成比例 = (开启率 + 二级及以上比例 + 三级比例) / 3
```

技能、模组各取最高分支，不累加分支；没有可用模组时将前两项之和除以 0.8。
分数范围 0–1，显示时乘以 100。持有率不参与评分；持有样本至少 100 人才使用统计，
缺失或不足显示暂无数据，排序取中性值 0.5。它反映玩家培养选择，是间接参考。
统计偏好先比较参考分，再比较达到目标比例、作业需求和候选键，每人一个目标。

调用凭证、技巧集、特训装置和特训邀请函从游戏物品表及 PRTS 道具页面取得范围，
同名物品按 ID 区分，未知范围不扩展为全部干员。自选包不显示库存／到期；培养券在
森空岛返回库存时才显示，没有库存记录仍可查看适用干员。材料提货券和芯片包不在推荐页分析，服务端保留目录和库存解析。

| 道具 | 适用条件 |
| --- | --- |
| 技巧集 | 已精二、技能七级、所选技能未专三；正在训练室专精的技能须在游戏内核对 |
| 特训装置 | 已精二且未满级 |
| 特训邀请函 | 未精二，提升至精二一级并保留技能等级 |
| 调用凭证 | 按对应范围优先补未拥有干员 |

培养券仅推荐适用星级，并按游戏特殊干员表排除不可用对象。作业偏好下，道具相关需求
乘以 `(1 + 养成参考分)`，同分比较参考分、对应精二／专三比例和候选键；
统计偏好先参考分再对应比例、作业需求和候选键。不操作游戏内道具或估算省下的理智。

2026 感谢庆典特别招募由独立开关控制，四个队列各 12 人按公告固定，不判断活动时间。
干员分为 `100 + 80 × 养成参考分 + 20 × 归一化作业需求`，需求除以四队最高个人需求。
展示原分；仅在队列平均分中将已拥有干员乘以 0.1，未拥有按原分，无需求记零。
队列按Ⅰ至Ⅳ展示，最高分可并列推荐，不执行招募或保存选择。

## 我的养成项目

每个账号／档案在当前浏览器保存最多 30 名干员，每人一个目标：精英阶段、等级、
一个技能的等级或专精，以及希望资源备齐的日期。暂不预算模组或专精训练耗时。
服务器校验上限与技能解锁阶段；关闭功能保留目标。

从排班培养建议或练度推荐导入时保留明确的等级和技能目标，仅精英化建议取该阶段一级。
组合建议整组加入；同名干员保留已有设置与顺序，超过 30 人时整次停止。
模组、潜能不能转成目标，只有这类缺口的条目不提供导入。存储异常时保留原记录并提示失败。
同页及其他标签同步目标变化；计算期间再改目标，完成后继续计算最新目标。
旧成本未匹配当前目标时不得用于日期或路线。

目标清单展示待提升练度与资源日期，材料、暂缓和顺序操作按需展开。
资源准备计划分材料获取、合成和每日安排；条件有效时默认折叠，缺项或生产方案读取失败时展开。
材料可查看完整路线；配方按所选用量展开且不扣库存，实际准备量仍以分配后的缺口为准。

库存和基建收入按目标顺序共享，第一项未暂缓目标为主要目标。
合成先抵扣成品，再按依赖处理加工；整批余量可用于后续目标，已预留用料不能重复分配。
“现在可完成”合并同材料步骤，“补齐资源后完成”保留待补资源的各次需求。
加工费用计入需求，副产物不计预期产出；芯片转换仅在已有可转换库存时使用。
每份芯片助剂需 90 红票；旧快照无来源时用 AP-5（30 理智、平均 21 张，周一／四／六／日）。

理智先准备非钱、经验材料，再补钱书，按整次刷取和国服开放日模拟，最长 180 天。
暂停或重排目标会重分库存并比较主要目标日期，提前天数可为零，无法确定时保留未知。
日期表示资源准备估计，未包含随机偏差、训练室、关卡解锁、领取和实际执行耗时，不承诺最短路线。

日收入取保存的真实排班，每份作战记录折算 1000 经验；优先净龙门币，否则扣已知日消耗。
金条净消耗受导入库存约束，收支缺失须提示核对供应，缺少完整日产量不推算日期。
未选方案时仅刷取，不补造基建收入。可选日常和临时方案：先生产更紧张的资源至补齐，
次日恢复日常；只有主要目标提前或首次能在 180 天内备齐才推荐临时方案。
调整偏钱／经验配置需有编辑权限，保留制造站总数并关闭自动产物重分配；
必须生成真实排班后再比较日期，采用或恢复方案均由用户主动执行。

“导出到 MAA”按顺序导出未暂缓目标，粘贴到 MAA“干员培养 → 读取剪贴板”。
它会追加目标，导入前检查重复；不依赖材料或日期计算，资料缺失先刷新，复制失败可手动复制。
格式对照
[`ParsePlan`](https://github.com/MaaAssistantArknights/MaaAssistantArknights/blob/d9f5be750da3d1e1d6790d85a046672cb7682be1/src/MaaWpfGui/ViewModels/UserControl/TaskQueue/OperProgressTaskUserControlModel.cs)：
JSON 数组含 `name`、`role`（MAA 职业名）、`elite`、`skill_level`、`skill_mastery`。
无职业时由 MAA 按名字匹配；8–10 转为所选技能专精 1–3，其余专精为零；
无技能或目标一级时 `skill_level` 为零。格式没有干员等级字段，等级仍需游戏内完成。

项目请求仍为 `POST /api/cultivation-plan`，`projects` 每项为
`operatorId`、`elite`、`level`、`skill`、`skillLevel`、`paused`、`deadline`，拒绝重复干员；
空数组用于首次目录读取。响应复用 `CultivationData` 并带 `projectOperators`，候选 `source: project`。

## 钱书平衡建议

账号模式统计全部已拥有干员，按星级组合目标：低星不练或满级，四／五／六星不练、
精二 40／50／60 或精二满级；默认低星不练、高星中间档，超过目标不计新增费用。
模组默认不开，可选常用／全部及一级至三级；常用指持有样本至少 100、开启率至少 50%，
不代表强度，选择不练的星级不新增模组需求。模组前置练度并入目标，费用不重复计算，阿米娅各形态共享培养取最高练度，
模组分别计费。统计、当前状态或费用不完整时暂停完整比例和日期，列明缺失项。

先计算目标总龙门币／经验，再扣库存，缺口最低为零。优先补库存覆盖较低项；
相同则同时准备，两项够用提示已备齐。零需求不输出 Infinity 或 NaN。
账号模式估算补齐两项缺口的最早天数；手动模式以 1.3∶1 为目标，
低于 1.2∶1 补钱，高于 1.4∶1 补经验，含边界的区间内保持平衡。
该参考源自升级和精英化；账号另含所选模组，不含合成费用和未来奖励。

两种模式使用当前档案最近排班的净日收入，读取失败标明仅刷关估算。
每天自然恢复 240 理智，LS-6／CE-6 每次 36 理智、主奖励 10000，LS-6 另含 432 龙门币。
CE-6 按周二／四／六／日、国服 04:00 换日，不跨未开放日囤理智。
账号模式只刷仍缺资源，受开放日预算约束，不额外刷经验获取附带龙门币；手动模式求首次达到或跨过目标比例的时间，
无法达到则提示调整产出。假设产出持续不变，不含活动、额外理智或培养消耗。

账号和手动 Tab 各自保留数据；手动输入总经验或四类作战记录（200／400／1000／2000），
点击计算后才应用。异步导入不切 Tab 或覆盖手动结果，草稿在 `sessionStorage` 按用户／档案隔离。
账号请求使用 `training: true`，不接受项目或作业条件、不跑推荐或完整路线；
同响应提供库存、练度、等级表和模组成本。切换目标在本地算，切账号丢弃旧响应。
等级累计逻辑共用 `src/lib/training-ratio.ts` 与 `src/data/training-level-data.json`。

## 材料需求趋势

`src/data/material-demand.json` 按新增内容日期汇总全部星级精英化上限、技能七级、
全部专三及每个模组三级的完整费用。转职仅新增专精，共享前置培养只计一次；
无普通材料费用的内容仍计入条目数。描述新增内容规模，不代表玩家实际消耗。

金紫材料递归拆为蓝材料，白绿折同系列蓝材料当量；不含副产品、加工龙门币、经验、
芯片、技能书或模组专用资源。快照 v2 的 `origins.direct/purple/gold` 按原费用品质归类，
逐材料相加等于 `amounts`，金配方中的紫原料仍归金来源。

默认趋势为最近六个完整月总量除以六，可选原月、三个月或十二个月；占比使用同窗口
全部蓝材料需求作分母，不按内容条目数平均。完整无需求月记零，无总需求占比未知；
窗口不足不画主线，未覆盖月底只显示原始值。明细和 CSV 保留真实读数。

默认纵轴以正值第 95 百分位的 1.5 倍识别极端峰值，再取其余最大值加 8% 顶部空间。
开启原始点时一并考虑；超出峰值裁切并标三角，不改写数值，可切完整线性纵轴。
详细图与 21 个独立零起点小图同步切换；支持触摸、方向键和月份选择。

年度变化固定比较最近 12 个完整月与前 12 月，另列六个月对比，不随选中月份或趋势窗口变化。
数量变化为 `(本期−前期)/前期`，占比变化为百分点；前期零需求比率未知。
首次正需求只作可观察历史起点，不宣称材料实装日；不足两完整年度不计算年度增幅或占比变化。
CSV 保留两期日期、可比状态、数量、占比、来源和用途，未知比率留空。

```sh
node --test scripts/material-demand-lib.test.mjs
node scripts/sync-material-demand.mjs
```

同步从同一游戏 SHA 读取干员、转职、物品、配方和模组表；干员日期来自
[PRTS 上线时间](https://prts.wiki/w/干员上线时间一览)，模组用 `uniEquipGetTime` 转北京时间。
记录资料日期、游戏 SHA 和日期页 SHA-256。缺日期、配方或结构异常时保留旧快照。
Sync Game Icons 工作流每日更新；历史按当前成本回溯。离线可加
`--input-dir <目录> --game-sha <SHA> --as-of YYYY-MM-DD`，目录放上述五表和 `operator_release_dates.html`。

## 数据部署与维护

### 首次导入

服务不自动全量爬取。先在 qqbot_manager 完成全量刷新，取得一致的 SQLite 备份与
`data/prts_costs_evidence-v3.json`。启用 WAL 时使用在线备份，不直接复制运行中的主文件：

```sh
python3 -c 'import sqlite3; source=sqlite3.connect("file:data/prts_difficulty.sqlite3?mode=ro", uri=True); target=sqlite3.connect("/tmp/prts-planning-export.sqlite3"); source.backup(target); target.close(); source.close()'
node scripts/import-prts-planning.mjs \
  --database /path/to/prts-planning-export.sqlite3 \
  --costs /path/to/prts_costs_evidence-v3.json \
  --output /var/lib/maatool/cultivation/prts-planning.json
```

配置 `MAA_PRTS_PLANNING_PATH` 指向输出；默认 `.cache/cultivation/prts-planning.json`。
目录持久化、不随发布覆盖，API 需读写权限。发布包可用
`server/dist/import-prts-planning.js`、`server/dist/sync-prts-planning.js`，需要 Node.js 24 和已安装依赖。

导入只读有效完成快照，缺详情或版本不符则失败；按成本缓存的 `game_sha` 下载资料，
企鹅物流国服常驻掉落要求至少 300 样本。校验后原子替换，不全量请求作业。
离线可加 `--assets <文件>`，含 `operators/recipes/farms/itemNames/potionValues`，
格式见 `scripts/prts-planning-lib.mjs` 的 `loadPlanningAssets`。未导入时提示等待，不自动全量下载。

### 更新

API 启动和北京时间零点仅在练度推荐及其父开关开启、配置读取成功时检查数据。
过期快照增量同步，当天数据复用；未导入跳过，失败保留旧数据，下次重试。
关停先取消并清理锁；多进程共用文件锁。手动更新：

```sh
node scripts/sync-prts-planning.mjs \
  --output /var/lib/maatool/cultivation/prts-planning.json \
  --reconcile 200
```

从最大 ID 取新增，详情最多每秒两次；默认每次复查 200 条历史并保存进度，
不保证当天全量识别修改。`--reconcile` 范围 0–2000；失败或锁占用返回非零且保留文件和游标。
游戏版本更新时增加 `--costs <新成本缓存> --refresh-assets true`。
强制终止可能留下 `.lock`，确认其中 PID 对应进程已停止后才能移除，不能只按时间删除。

已有快照需要手动全量更新时：

```sh
node scripts/fetch-prts-planning.mjs \
  --base /path/to/current-prts-planning.json \
  --output /path/to/prts-planning-full.json
```

输入输出必须不同；每页 200 条、间隔至少 500ms、临时错误最多重试三次。
分页已含需求，不逐份取动作；去重并排除隐藏／删除，保留上游发布时间，不以同步时间替代。
缺有效时间或分页异常不替换输出。上传后核对 SHA-256、数量与缺失时间为零，
独占生产 `.lock`、备份旧文件，在同目录原子重命名并保留权限；锁忙则等待，勿删活动锁。
下一次每日维护构建新证据，需要立即生效时重启 API。

### 公共缓存与运行限制

| 数据 | 位置与更新 |
| --- | --- |
| 作业证据与查询 | 快照旁 `<快照名>.evidence-v1.sqlite`，Node 内置 SQLite；可重建，不是历史归档 |
| 自选项目／钱书游戏目录 | 同目录 `project-game-data.json`，目录版本 2；统一游戏 SHA，每日按需更新，缺已拥有干员时立即刷新 |
| 一图流统计 | 同目录 `operator-statistics.json`，每日按需刷新；失败保留有效旧值和状态 |
| 特殊道具目录 | 同目录 `special-item-catalog.json`，PRTS 按 `itemId` 查询并批读，校验后原子替换 |

游戏目录失败只复用能覆盖当前干员的有效缓存，否则返回可重试的
`503 cultivation_data_unavailable`。公共缓存不含库存、练度或凭据，账号缺口按请求计算，HTTP 为 `no-store`。

完整解析／构建在临时子进程完成并退出，再由读取进程加载精简证据；不要把作业正文送入请求路径。
证据按整数索引复用并压缩，分批校验写入，避免累积原始正文和完整 JSON 副本。
每 API 进程最多一项读取和一项构建，忙返回 `503 cultivation_busy`；读取和首次构建期限 90 秒，
读取超时为 `504 cultivation_timeout`，客户端断开会终止读取并取消未完成构建，取消写入须等事务／锁清理。读取空闲 60 秒退出；
读取／构建老生代上限为 512／256 MiB，不是总内存上限。JSON 在读取进程序列化为 UTF-8 经二进制 IPC 返回。
发布包必须包含 `server/dist/cultivation-worker.js`。

证据构建在同一 SQLite WAL 事务发布，失败回滚，更新期间读旧版；损坏查询重算，
损坏证据从原快照重建。推荐时效按北京时间零点，文件修改时间／大小变化触发校验构建。
读取进程最多缓存两份、合计 4 MiB 压缩查询；SQLite 保留最多 64 组、压缩查询按 64 MiB 淘汰，
单组超大结果仍可保留，运行时和数据库文件会更大。同机可共享目录，跨主机各自构建。
旧快照缺发布时间不参与推荐；无时区按北京时间，不用作业 ID 推测。
