# 围观价值窗口 Handoff

状态：待实现的产品与技术方案。本文描述一个独立 V2 页面；观察会话、窗口接口和个人展示均待开发。

本页回答：**从你打开这个页面开始，全站方案预计又积累了多少资源？其中你的方案贡献了多少？**

总产出、历史构造、时间积分、开关、快照和个人身份隔离以[全站基建价值时钟](value-clock-handoff.md)为准。其他独立页面为[优化增益时钟](optimization-gain-clock-handoff.md)和[全站基建工厂](production-factory-handoff.md)。

## 1. 定位与交付目标

把巨大的历史累计转换成一段用户能亲眼感受到的变化：页面从真实的观察起点开始，经过几十秒，就能看到新增的龙门币、作战经验、合成玉和价值。

首版包含独立公开页面、从零开始的观察计时与新增读数、当前速率、全站历史总量的次要展示、登录后的当前档案贡献、重新开始观察、分享入口和全屏。无需登录即可看到完整的全站观察体验。

本页的计时表示“从这次观察开始经过的时间”，包括页面隐藏和断网期间。它不统计用户盯着屏幕的时间，不采集注意力，不将页面停留当作基建已经执行的证据。

不新增行为埋点、跨设备追踪、排行榜、观察奖励或自动截图上传。观察起点保存在当前标签页，不写入用户长期档案。

## 2. 入口与文案

- section：`value-window`。
- 公开地址：`/v2?section=value-window`。
- 工具目录、其他三页和价值时钟的“从此刻观察”链接均进入本页。
- 使用同一个 `base_value_dashboard` 开关；公开读取与个人操作权限按共享规则处理。
- 公开分享只包含页面入口，不包含用户 ID、档案、原观察起点或私人贡献。收件人打开后开始自己的观察。

| 位置 | 建议文案 |
| --- | --- |
| 标题 | 看见每一秒的积累 |
| 开场 | 从你打开这里开始 |
| 已建立观察 | 从 HH:mm:ss 开始观察，已过去 MM:SS |
| 主读数 | 这段时间，全站方案预计新增 |
| 主单位 | 等效理智 |
| 资源行 | 龙门币净收入、作战经验、合成玉 |
| 个人区 | 其中，你的方案预计贡献 |
| 访客入口 | 登录看看我的贡献 |
| 重新开始 | 从现在重新观察 |
| 常驻口径 | 按本站保存的排班连续运行估算 |

不要写“你看着屏幕的这 30 秒”“刚刚实际到账”或“因你围观创造的收益”。用户打开页面不会增加全站产出。

## 3. 页面结构与视觉节奏

```text
看见每一秒的积累                     四页导航         全屏展示

                  从 13:08:06 开始观察，已过去 00:42

                         这段时间预计新增
                             +123.45
                            等效理智

          龙门币净收入              作战经验              合成玉
              新增                    新增                新增

                  其中，你的方案预计贡献 +1.23
                  当前档案名称         查看我的方案

            全站累计预计产出价值             当前每分钟预计产出

      从现在重新观察       分享这个页面       了解口径
```

示意数字不得作为上线默认值。

主读数始终表示本次观察窗口，不让历史总数抢占第一层级；计时是第二焦点，帮助用户理解为什么数字变化。登录后的个人贡献与全站新增使用不同文字标签，不能简单叠加到总量上。

沿用[设计规范](../design.md)的字体、主题、铜色强调和等宽数字。开场可以轻量显现一次，随后只更新读数；不每隔几秒弹出“又多赚了……”的营销提示，不用环绕粒子制造虚假热闹。

### 响应式

- 手机顺序为观察时间、窗口价值、三个资源新增、个人贡献、当前速率及次要链接。
- 资源行可折成一列或两列，但每项始终有数值与单位；不能因样本少而隐藏合成玉的真实 0。
- 200% 字号允许计时和起点分行；小时累计超过两位时保持完整，不截掉时间前缀。
- 桌面全屏保留重新开始、暂停显示、退出全屏及数据状态；这些操作不能只在鼠标悬停时出现。

## 4. 观察会话的精确定义

### 建立起点

1. 首次进入当前标签页的本页面，读取共享生产快照。尚未成功读取时显示“正在开始观察”，不启动一段假计时或本地随机增长；统计尚未启用或数值不可用时保持对应状态，不建立观察起点。
2. 用服务端成功响应中真实的 `as_of` 作为观察起点 `started_at`，记录对应 `series_id`、`metric_version`。第一帧窗口读数为 0。
3. 共享接口应将内部缓存聚合投影到本次响应时刻，不能拿几十秒前的缓存锚点冒充刚建立的观察起点。
4. 之后携带起点与统计系列读取窗口差值；浏览器只在快照有效时间内向前估算。

初次请求前的等待不计入窗口。产品不需要“打开到第一帧必须为零毫秒”的承诺；需要的是起点与数字对应同一时刻。

### 保存与恢复

- 只在 `sessionStorage` 保存公开观察元数据：`started_at`、`series_id`、`metric_version`，以及本地结构版本；不保存个人数值、用户 ID 或 UID。
- 同一标签页刷新或临时去其他工作台页面后返回，继续原观察窗口，并先向服务端核验。页内文本明确显示起点，避免被误解为重新开始。
- 新标签页独立建立观察起点；分享入口去掉观察状态。若浏览器复制了标签页存储，则按普通刷新恢复，用户仍可主动重新开始，不为识别复制标签页增加追踪机制。
- 存储不可用时在内存中维持当前观察，刷新后重新开始，页面正常可用，不阻塞主流程。
- 系统时间被调整时，用服务端锚点加单调经过时间显示计时；刷新后重新校准。客户端时间不能改变累计或提交一个任意过去时间。

### 时长、午夜与离开

- 一次观察最长 24 小时。到达 `started_at + 24h` 后，窗口数值与计时封顶，显示“已完成 24 小时观察”，提供重新开始。
- 北京时间午夜重置全站“今日累计”，不重置本次观察。窗口可以跨日，仍只表示同一个起点以来的变化。
- 页面隐藏时停止动效和轮询。观察在时间意义上继续；回来后重新读取当前窗口，不回放离开期间的动画。
- 离线时遵守快照有效期，不能无限延续旧速率；超过有效期后暂停窗口读数，观察时长可以继续，但必须同时标明数据截至何时。
- 回到前台时若已超过 24 小时，服务端返回封顶窗口，不能把过去几天都计入一次观察。

### 重新开始

点击“从现在重新观察”后，读取新快照，以服务端确认的时刻替换原起点。成功后计时与窗口值一起归零；失败保留原窗口并给出重试。

这个操作不删除任何全站或个人收益账本，只重置本标签页的观察起点，因此不需要确认弹窗。多次点击期间只保留一个进行中的操作，不改变历史账本或产生收费请求。

## 5. 窗口数值与时间契约

窗口值必须是服务端账本在同一口径内的区间积分：

```text
end = min(本次快照时刻, started_at + 24 小时)
窗口新增 = 账本累计(end) - 账本累计(started_at)
```

实际服务端可以按区间积分直接计算，结果必须等价。开始后新加入、结束、换方案、库存截止与样本人数变化都应包含在积分中；不能把“现在每秒速率 × 总观察时间”作为整段窗口值。

例如：前 20 秒每秒 1 等效理智，之后 20 秒每秒 2，则 40 秒新增为 60；不能显示 80。刷新页面、重新连接和更换浏览器帧率都不能改变这个结果。

### 接口约定

公开使用共享接口：

```text
GET /api/site/value-clock?view=production&since=<ISO时间>&series_id=<系列ID>
```

查询参数是本次观察的计算条件，不是公开账号或行为记录。服务端必须验证：起点属于指定的当前统计系列、未早于真实统计起点、未晚于服务端当前时间。任意旧窗口最多计算其起点后的 24 小时；不能被用户参数扩大成无上限查询。

响应保留共享快照字段，并增加：

| `window` 字段 | 约定 |
| --- | --- |
| `started_at` | 服务端接受的起点 |
| `ends_at` | 起点后 24 小时的观察上限 |
| `as_of` | 本次窗口读数实际截止时刻，不晚于 `ends_at` |
| `totals` | 从起点到 `as_of` 的资源与价值差值向量 |
| `rates_per_second` | 当前可继续估算的窗口速率；封顶时为 0 |
| `valid_until` | 共享截止时刻与观察上限中的更早值 |
| `status` | `running` 或 `completed` |

起点非法返回明确的 `400`。统计系列改变返回可识别的 `409 statistics_series_changed`，客户端进入“口径已更新，请重新开始观察”状态，不跨系列相减。

首版不新增服务端观察会话表或观察创建接口。服务端根据已验证的时间与既有区间账本计算，观察次数不会成为业务统计。

### 查询与本地派生

- 公开查询键为 `['public', 'value-clock', 'production', series_id, started_at]`，与共享契约一致，防止口径变化时命中旧结果。
- 起点是固定会话条件，不能每秒把当前时间写入 query key。轮询仍为页面可见时每 30 秒一次。
- 服务端窗口结果是权威锚点；本地显示为 `window.totals + 当前速率 × 有效经过秒数`，最多推进到窗口有效时刻。
- 计时可每秒更新，价值按共享最多每 250 毫秒的策略更新；组件不能通过每次定时回调“加一点”形成独立账本。
- 同一统计口径的 revision 校正时重新计算整个窗口，允许读数减少并显示“统计已校准”；原起点保留。
- 估值或统计系列改变时不把新总量减旧起点。冻结原窗口，用户确认重新开始后才建立新起点。

## 6. 个人贡献与身份变化

### 展示范围

首版个人区仅展示当前选中游戏档案对应的贡献，标签保留档案名称。它使用与全站窗口相同的起点和截止时刻，说明“其中”是全站窗口的组成部分，而不是另加的一份产出。

个人区由用户接口计算：

```text
GET /api/user/value-clock?profile_id=<id>&since=<ISO时间>&series_id=<系列ID>
```

服务端以已认证用户的当前归属校验档案，再读取同一统计身份的历史区间。该身份没有产出区间时贡献为 0；从未产生可用数据与读取失败分别展示，不能把所有失败都变成 0。

### 登录、退出与换档案

- 访客只看到公开窗口与登录入口，不发个人查询。登录后的个人贡献可覆盖同一观察窗口内该账号已计入的历史区间，不要求重新开始全站观察。
- 登录成功保留全站观察起点；从授权接口重新读取个人数值，不从登录前页面猜测。
- 切换档案后全站窗口继续，个人区立即移除旧档案读数，再显示新档案的加载／结果；不把两个档案相加。
- 退出登录删除个人缓存与页面读数，公开窗口继续；迟到请求不能恢复私人内容。
- 个人读取失败不阻塞公开窗口。重新登录、切换账号或档案只重新读取对应历史账本。
- 个人请求与全站响应有时间差时，按两者共同的有效时刻显示；无法对齐时保留独立截至时间，不将不同截止时间的数值并排暗示为精确分解。

首版不增加贡献百分比，避免净额、不同截止时刻和负收益使百分比难以解释。个人贡献来自本站保存的排班历史；没有历史时提供生成排班的入口。

## 7. 显示暂停、低增长与异常

| 场景 | 展示与恢复 |
| --- | --- |
| 初始接口未成功 | “正在开始观察”或失败重试，不起假计时 |
| 已有观察记录恢复 | 先读取并校验原窗口，不闪出上一身份个人值 |
| 全站当前没有活动方案 | 窗口保持真实累计，速率 0，说明暂无方案正在计入 |
| 增长不足一位显示精度 | 保留真实值，可显示当前每分钟速率或轻量平均进度，不增加虚假小数 |
| 断网且快照仍有效 | 在有效期内继续显示估算，并提示读取失败 |
| 快照失效 | 冻结窗口产出，显示“数据截至 HH:mm:ss，等待更新”；时长与数据状态分开 |
| 手动暂停动态显示 | 同时冻结计时与读数画面，注明“画面已暂停”；恢复时取当前窗口 |
| 达到 24 小时 | 数据和计时封顶，显示观察完成，可重新开始 |
| 当前口径发生改变 | 保留明确标记的最后读数，提示重新开始，不静默归零 |
| 重新开始请求失败 | 旧窗口保留，不产生半归零状态 |
| 个人查询失败 | 全站继续，个人区独立重试 |

自然的净额可能为负，窗口仍需保留符号。不能因为标题想强调“积累”就删除负向成本，或将历史校正当成动画 bug 用最大值覆盖。

## 8. 无障碍、全屏与分享

- 计时和连续增长数字不做逐秒读屏播报，提供完整文本、单位与“读取当前值”的明确方式。
- 减少动态效果时去除翻牌、位移和进度绘制，数字最多每秒直接更新一次；所有内容与操作保留。
- 按钮有可见焦点和至少 44×44 CSS px 触控面积；四页导航、重新开始、暂停、分享和全屏都可键盘访问。
- 全屏只是布局变化，不创建新会话；退出后焦点返回原按钮，观察起点和查询继续。
- 分享按钮优先使用平台分享能力，失败或不支持时提供复制链接。只有平台返回完成或复制实际成功才显示相应状态；取消分享保持安静。
- 分享的是公共入口，不上传截图、不拼接私人贡献和起点；用户自行截图时界面已有“预计”标签和起点，避免图片失去统计含义。

## 10. 验收场景

### 时间与数值

| 场景 | 预期 |
| --- | --- |
| 首次成功响应 | 起点来自服务端，窗口从真实 0 开始 |
| 固定速率 2／秒，经过 30 秒 | 增加 60，不受渲染帧率影响 |
| 前 20 秒 1／秒、后 20 秒 2／秒 | 窗口为 60，不是 80 |
| 中途加入／到期／换方案 | 按各时间区间积分，下一快照正确校准 |
| 刷新或离开本页再回来 | 同标签页恢复原起点，先读取当前窗口 |
| 午夜 | 今日值换日，观察不归零 |
| 页面隐藏 10 分钟 | 无轮询和动效；恢复后读取完整合法窗口，不回放动画 |
| 断网超过有效期 | 产出冻结，数据截至时间清楚；恢复后校准 |
| 系统时钟调快／调慢 | 观察产出不被本机时间操纵 |
| 超过 24 小时后回到前台 | 返回起点后 24 小时的封顶结果 |
| 同口径修订 | 重新计算窗口，允许校正，起点保留 |
| 统计系列改变 | 不跨版本相减，提示重新开始 |
| 手动重新开始失败 | 旧窗口、起点和数字保留 |

### 个人与交互

- 访客打开不调用用户接口；登录后读取同一窗口内的授权贡献。
- A 档案切换到 B 时，A 值立即移除；退出、换用户及迟到请求均不泄露旧数值。
- 全站与个人截至时间一致或明确分别标注；不能把不同窗口标成精确“其中”。
- 新窗口、恢复窗口、真实零、负净额、无活动账号、存储不可用、分享取消／失败均验证。
