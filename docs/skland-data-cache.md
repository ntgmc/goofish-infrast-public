# 森空岛共享数据

登录与上游请求统一经过[独立连接服务](skland-connector.md)，其部署位置决定请求出口。
排班导入、基建设施、养成建议、养成项目、钱书平衡、仓库估值和培养成本共用服务端账号快照。
缓存归属于网站用户和明日方舟 UID；每次读取仍通过当前档案校验归属、绑定、授权和可用状态。
同一用户的同 UID 档案共享数据，排班配置、手动覆盖、养成目标和计算结果仍各自保存。

## 绑定角色解析

`GET /api/v1/game/player/binding` 的解析由
`server/handlers/skland-client.ts` 的 `getArknightsBindings()` 负责：只读取
`appCode === "arknights"` 的 `bindingList`，列出有效 UID 并去重；默认角色排在前面。
`defaultUid` 为空时仍使用各绑定记录的 UID，只有一条绑定且其 UID 缺失时才回退到
`defaultUid`。昵称和渠道来自对应记录，不使用 `endfield` 的角色补齐。
多角色交给现有账号选择与确认流程，不因缺少默认 UID 判定为未绑定。

## 读取和刷新

- 首次使用自动读取角色数据及养成库存。
- 最近成功获取未超过 15 分钟时复用快照，不访问森空岛个人数据接口。
- 15 分钟至 24 小时之间先使用上次数据，按需统一更新；普通工具页面进入和重新获得焦点时检查服务端版本。
- V2「森空岛数据」页进入、回到前台和手动刷新时主动读取上游最新数据，仍遵守同账号请求合并与刷新间隔。
- 超过 24 小时的数据不能用于新的库存分析或养成计算。
- 各页面的“刷新森空岛数据”更新同一账号的角色和库存；成功后至少间隔 30 秒，失败后至少间隔 60 秒再访问上游。
- 角色与库存分别保留最近成功时间。部分更新失败时保留该部分的有效旧数据和时间，首次失败保持不可用，不按零库存处理。
- 没有按账号运行的定时拉取任务；已有维护任务每小时清理超过 24 小时未更新的快照。

页面展示数据获取时间，重新计算不改变该时间。快照只有一个当前版本，版本号由数据库序列生成。
物品定义和干员培养材料属于公共资料，在服务端内存缓存 24 小时；失败不缓存，干员资料最多保留 600 个条目。

## 接口

`GET /api/user/skland/snapshot?profile_id=...` 读取共享数据，缺失时自动导入，过期时按上述规则更新。

`POST /api/user/skland/snapshot/refresh` 接收 `{ "profile_id": "..." }`，主动统一刷新。
内部页面后台更新可传 `force: false`，继续遵循新鲜度规则；手动刷新也遵守刷新间隔。

响应包括 `uid`、`version`、`game`、`inventory` 和 `retryAt`。
每组数据包含 `fetchedAt`、`state`（`fresh`、`stale`、`expired`、`unavailable`）及最近更新错误。
库存另外包含物品数量、龙门币、折算后的作战经验和物品名称。名称复用森空岛公共物品定义缓存；定义读取失败时保留数量，页面使用本地道具资料补充名称，未知道具显示「未命名道具」。列表不显示道具编号。
`game.data` 是经过字段筛选的角色概览和基建状态，包含理智、角色统计、日常/周常、剿灭与保全派驻进度、公开招募，以及房间等级、生产类型、待收取数量、进驻干员与心情、无人机、线索和训练。缺失字段保持不可用，不按零值补齐。角色、进度、房间和居民分别校验；空闲时的负数时间、空值或单个异常房间不会使其他有效数据全部丢失。
响应不返回原始角色资料和授权凭据，HTTP 使用 `Cache-Control: no-store`。
展示接口允许角色或库存部分失败，保留成功部分和各自时间；计算业务仍要求所需库存有效，失败时返回可操作的错误，不返回空库存冒充成功。

原有 `POST /api/cultivation-plan`、仓库估值和设施接口继续提供业务结果，个人数据统一从快照读取。
养成线程只接收计算所需的数据、源数据时间及版本，不接收森空岛凭据。
钱书平衡读取共享库存，并通过养成接口的 `training: true` 模式读取同一快照的已持有干员、
等级表及模组费用；切换培养目标在前端计算，不运行作业推荐或完整养成路线。

## 页面与基建配置导入

V2 个人菜单的「森空岛数据」按概览、游戏背包、当前基建分组。游戏背包与网站道具背包分别进入。生产设施按游戏地图位置排列，显示获取时的状态，森空岛自身的同步可能有延迟。

游戏背包按基础资源与作战记录、养成材料、模组/芯片/技能书和其他道具分组，支持名称搜索。道具名称、分类、排序和图标映射来自公开游戏表，通过 `pnpm run sync:cultivation-icons` 同步生成 `src/data/skland-items.json` 和本地图片；未收录的图标使用通用道具图形。

合成玉、至纯源石、寻访凭证、十连寻访凭证、高级/资质凭证、招聘许可、通用凭证及中坚寻访凭证在接口未返回时提供手填输入。用户点击「保存资源数量」后，将非负整数保存至当前浏览器的 localStorage，按网站用户 ID 与游戏 UID 隔离；留空表示未记录，填写 0 表示已知为零。刷新和页面重开保留记录，其他浏览器不共享。写入失败会提示尚未保存，不清空填写内容。

手填记录只用于背包查看，不作为养成计算或仓库估值的接口库存；接口后续返回同一道具时优先显示接口数量，保留原手填记录。清除浏览器站点数据会删除手填记录。

配置编辑器提供「一键从森空岛导入」。`POST /api/user/skland/facilities` 主动刷新游戏与库存数据，并一次返回 `rooms`、`configuration`、`configuration_error`、`fetched_at` 和 `refresh_warning`；读取本身不改写工作区。完整配置包含房间数量、受支持的等级、九间生产设施的地图位置、各房间当前生产类型，以及 `intermediate_inventory` 中的赤金、源石碎片、固源岩和龙门币。库存复用绑定、刷新干员时的解析逻辑。前端一次应用这些字段，沿用原有自动保存、编辑权限、班次和策略设置，无须再次获取房间或库存。

V2 导入后保留当前页签。「检查排班设置」直达执行方式，使用 MAA 时可选择换班频率。下方可打开「查看房间与回收站」核对布局，并按游戏内情况手动设置回收站等级。导入保留当前 `recycling_station_level`，未设置时按未建造处理。

导入只接受当前排班器已支持的 243、333 及三种 252 等级组合。芯片生产、未知/未设置配方、不支持的布局或库存不可用时会给出说明并保留原配置。上游刷新失败但旧数据仍有效时，明确提示并显示房间和库存中较早的数据获取时间。有效库存中未持有的物品按零导入，读取失败不按零库存处理。导入请求在切换档案、进入只读状态或卸载时取消，迟到响应不能覆盖新的配置。

## 授权恢复

森空岛数据、养成建议、养成项目、钱书平衡和仓库估值在正常状态显示刷新操作；档案已标记授权失效，或读取接口返回 `skland_credential_invalid` 后，原位显示「重新授权」及失效提示。基建配置导入和干员管理同样将原操作替换为重新授权；生成页的授权错误提供直接恢复入口。网络或上游服务故障保留重试，网站登录过期引导重新登录，不按森空岛授权失效处理。

重新授权弹窗在扫码前显示当前绑定的游戏昵称、UID 和服务器，扫码后核对实际返回的账号。扫码和凭据预览接口通过 `purpose: "reauthorize"` 生成专用待确认记录。预览及确认读取森空岛绑定列表并遵守原有 UID 校验和风控规则；确认事务只更新当前档案的凭据和授权状态，保留绑定时间、上次干员导入时间、工作区配置、干员、练度覆盖和历史结果。取消、超时、档案冻结或 UID 不一致时不能提交。确认后使共享数据失效，打开的数据页重新读取，保留当前页的筛选和目标；数据更新失败可重试刷新，无需重复授权。首次绑定和主动导入继续使用原有流程。

数据按网站用户和游戏 UID 共享，授权错误按档案保存。仓库估值使用当前选择的档案恢复授权；授权响应只合并档案元数据，保持活动档案、配置草稿和工具输入。其他标签页通过授权更新通知重新读取档案状态，并按原有版本通知更新数据。

## 业务写入

统一刷新只更新游戏数据。排班页原有导入操作继续将快照应用到排班工作区，按原有规则更新干员、练度覆盖与部分配置。
`POST /api/user/skland/import/refresh` 的 `skland_import` 额外返回 `credential_verified_at`：
仅当本次请求使用当前档案的凭据成功获取游戏数据时返回验证时间；复用持久化快照或其他档案的刷新结果时返回 `null`。
该验证标记不写入快照，也不作为凭据持续有效的保证。游戏数据刷新失败但仍可使用旧数据时，返回 `refresh_warning`，保留原获取时间。
干员管理抽屉的刷新时间使用绑定记录的 `last_imported_at`；上传 MAA 文件、修改配置和失败请求不会推进该时间。
进入其他工具、后台更新、修改养成目标或推荐条件都不会改写排班配置，也不会重新拉取森空岛个人数据。
养成结果按最新快照重新计算，并保留未提交的输入；已保存的排班结果维持生成时的内容。排班培养建议页通过 `GET /api/user/results/:id?profile_id=...&training_costs=latest`，按当前档案的干员和共享库存重新核算材料、缺口及回本时间；读取先校验结果归属和培养建议权限，沿用该结果的诊断券权益。页面进入、库存版本变化和手动刷新会更新核算，无须重新生成排班。已达到目标精英阶段的建议标记「已完成」，组合建议须全部成员达到目标；已完成项排在待培养项后，保留原解释，并从培养顾问候选及加入养成项目入口移除。练度缺失或未达标时不按材料齐备判断完成；排班收益、历史保存内容、下载和已生成的 AI 解读保持原记录。库存解析与森空岛背包共用校验，读取失败或过期时不按零库存处理。已打开的森空岛数据页在手动刷新后可查看同账号的变化。角色与库存按各自成功获取时间分别比较；没有新值的部分不参与。养成项目按同一组目标比较两份计算数据，材料备齐按目标顺序分配后的库存判断。变化摘要只保存在当前页面，可按需打开。

仓库页面自动展示估值时不贡献统计样本。用户主动分析且同意贡献时才执行样本写入，
样本时间使用库存获取时间，相同或更早的库存不会重复更新已有样本。

## 并发和数据生命周期

同一 API 进程按用户和 UID 合并正在执行的刷新，不同进程通过 PostgreSQL advisory lock 共享刷新结果。
页面离开只取消自己的业务计算或等待，不终止其他页面正在使用的共享刷新。
前端通过共享内存状态和 `BroadcastChannel` 同步版本；接口获取的个人数据不写入浏览器持久化存储。用户主动填写的背包资源按上述规则保存在当前浏览器。

数据库表 `skland_snapshots` 保存经过校验的角色和库存响应，记录结构版本为 1，不能识别的版本按缓存缺失处理。凭据仍只在现有绑定记录中加密保存。
首次绑定确认前不写入持久化快照；确认导入成功时在同一事务中建立快照。

清除凭据、变更绑定或凭据、冻结或归档档案、删除档案会通过数据库触发器使相关快照失效。
刷新写回前锁定并校验原档案及凭据，清除授权后的迟到响应不能恢复缓存；
排班刷新应用到工作区前也再次核对授权。账号删除通过外键级联删除快照，个人数据导出包含当前快照。

数据库结构版本为 `2026-10-17.1`。部署时先完成受控迁移，再启动新应用；历史迁移记录与校验和保持原样。
