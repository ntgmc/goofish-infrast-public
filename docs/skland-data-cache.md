# 森空岛共享数据

排班导入、基建设施、养成建议、养成项目、钱书平衡、仓库估值和培养成本共用服务端账号快照。
缓存归属于网站用户和明日方舟 UID；每次读取仍通过当前档案校验归属、绑定、授权和可用状态。
同一用户的同 UID 档案共享数据，排班配置、手动覆盖、养成目标和计算结果仍各自保存。

## 读取和刷新

- 首次使用自动读取角色数据及养成库存。
- 最近成功获取未超过 15 分钟时复用快照，不访问森空岛个人数据接口。
- 15 分钟至 24 小时之间先使用上次数据，按需统一更新；页面进入和重新获得焦点时检查服务端版本。
- 超过 24 小时的数据不能用于新的库存分析或养成计算。
- 各页面的“刷新森空岛数据”更新同一账号的角色和库存；成功后至少间隔 30 秒，失败后至少间隔 60 秒再访问上游。
- 角色与库存分别保留最近成功时间。部分更新失败时保留该部分的有效旧数据和时间，首次失败保持不可用，不按零库存处理。
- 没有按账号运行的定时拉取任务；已有维护任务每小时清理超过 24 小时未更新的快照。

页面展示数据获取时间，重新计算不改变该时间。快照只有一个当前版本，版本号由数据库序列生成。
物品定义和干员培养材料属于公共资料，在服务端内存缓存 24 小时；失败不缓存，干员资料最多保留 600 个条目。

## 接口

`GET /api/user/skland/snapshot?profile_id=...` 读取共享数据，缺失时自动导入，过期时按上述规则更新。

`POST /api/user/skland/snapshot/refresh` 接收 `{ "profile_id": "..." }`，主动统一刷新。
内部页面后台更新可传 `force: false`，继续遵循新鲜度规则；手动刷新也遵守刷新间隔。

响应包括 `uid`、`version`、`game`、`inventory` 和 `retryAt`。
每组数据包含 `fetchedAt`、`state`（`fresh`、`stale`、`expired`、`unavailable`）及最近更新错误。
库存另外包含物品数量、龙门币及折算后的作战经验。响应不返回原始角色资料和授权凭据，HTTP 使用 `Cache-Control: no-store`。
当前业务需要的库存不可用时返回可操作的错误，不返回空库存冒充成功。

原有 `POST /api/cultivation-plan`、仓库估值和设施接口继续提供业务结果，个人数据统一从快照读取。
养成线程只接收计算所需的数据、源数据时间及版本，不接收森空岛凭据。
钱书平衡直接读取库存接口，不再运行完整养成计算。

## 业务写入

统一刷新只更新游戏数据。排班页原有导入操作继续将快照应用到排班工作区，按原有规则更新干员、练度覆盖与部分配置。
`POST /api/user/skland/import/refresh` 的 `skland_import` 额外返回 `credential_verified_at`：
仅当本次请求使用当前档案的凭据成功获取游戏数据时返回验证时间；复用持久化快照或其他档案的刷新结果时返回 `null`。
该验证标记不写入快照，也不作为凭据持续有效的保证。游戏数据刷新失败但仍可使用旧数据时，返回 `refresh_warning`，保留原获取时间。
干员管理抽屉的刷新时间使用绑定记录的 `last_imported_at`；上传 MAA 文件、修改配置和失败请求不会推进该时间。
进入其他工具、后台更新、修改养成目标或推荐条件都不会改写排班配置，也不会重新拉取森空岛个人数据。
养成结果按最新快照重新计算，并保留未提交的输入；已保存的排班结果维持生成时的内容。

仓库页面自动展示估值时不贡献统计样本。用户主动分析且同意贡献时才执行样本写入，
样本时间使用库存获取时间，相同或更早的库存不会重复更新已有样本。

## 并发和数据生命周期

同一 API 进程按用户和 UID 合并正在执行的刷新，不同进程通过 PostgreSQL advisory lock 共享刷新结果。
页面离开只取消自己的业务计算或等待，不终止其他页面正在使用的共享刷新。
前端通过共享内存状态和 `BroadcastChannel` 同步版本；个人数据不写入浏览器持久化存储。

数据库表 `skland_snapshots` 保存经过校验的角色和库存响应，记录结构版本为 1，不能识别的版本按缓存缺失处理。凭据仍只在现有绑定记录中加密保存。
首次绑定确认前不写入持久化快照；确认导入成功时在同一事务中建立快照。

清除凭据、变更绑定或凭据、冻结或归档档案、删除档案会通过数据库触发器使相关快照失效。
刷新写回前锁定并校验原档案及凭据，清除授权后的迟到响应不能恢复缓存；
排班刷新应用到工作区前也再次核对授权。账号删除通过外键级联删除快照，个人数据导出包含当前快照。

数据库结构版本为 `2026-10-17.1`。部署时先完成受控迁移，再启动新应用；历史迁移记录与校验和保持原样。
