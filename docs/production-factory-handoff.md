# 全站基建工厂 Handoff

状态：待实现的产品与技术方案。本文描述一个独立 V2 页面，页面、动画与接口接入均待开发。

本页回答：**本站保存的基建方案，合起来每时每刻预计在生产哪些资源？**

历史构造、自动更新、资源向量、时间快照、开关和持久化统一遵循[全站基建价值时钟](value-clock-handoff.md)。相关独立页面：[优化增益时钟](optimization-gain-clock-handoff.md)、[围观价值窗口](value-window-handoff.md)。

## 1. 定位与交付目标

以一座“联合基建”的流水线展示资源的来源、消耗和产出，让用户先看懂龙门币、作战经验、合成玉，再理解总等效价值。适合桌面全屏、网站展示与活动演示，也必须在手机上完整使用。

本页与价值时钟共用相同数据，只改变呈现方式；页面中每一个数字都应能与同一时刻的价值时钟对上。流水线表示长期平均生产节奏，不代表正在监听游戏、真实订单完成、干员动作或在线人数。

首版交付：三个资源链路、当前速率、累计资源、统一总价值、生产阶段说明、低频产出进度、资源详情、全屏与暂停动态显示。页面打开不发起排班、导入或游戏请求。

不做可拖拽建筑编辑、干员漫游、伪实时订单日志、随机弹出的玩家昵称、游戏地图和声音。复用项目现有资源图标，不新增插画或 3D 依赖。

- 沿用共用 `base_value_dashboard` 开关与共享时间账本，复用已有历史和后续保存的排班。

| 主状态 | 当前预计每分钟产出 |

## 3. 页面结构

### 桌面与全屏

```text
全站基建工厂                      四页导航      暂停动态显示   全屏

        当前纳入 X 个游戏账号        当前预计价值 / 分钟

   赤金生产 ── 赤金消耗 ── 贸易收款       龙门币净收入
      速率          速率        速率           累计

   作战记录生产 ────────── 作战经验       作战经验
            平均进度          速率           累计

   源石碎片生产 ── 碎片消耗 ── 合成玉     合成玉
        速率          速率       速率         累计

               累计预计产出价值：X 等效理智

   长期平均产出说明       数据更新时间       查看资源明细
```

每条链路是一个有标题的横向区域，生产、消耗和产出用节点及连线表达；不要把每个节点都放进重复卡片。三条链路共用对齐规则，明确累计和速率的不同位置。

视觉仍遵循[设计规范](../design.md)和 [tokens.css](../tokens.css)。铜色用于生效进度和主要数值；节点、连线采用现有语义色。资源图标本身可保留识别颜色，不用整屏变成游戏 HUD。优先采用轻量 SVG 或现有组件组合，数值文本保留在语义 DOM 中，不为装饰引入 Canvas/WebGL 引擎。

### 手机与窄屏

- 三条链路按龙门币、作战经验、合成玉顺序纵向排列，每条以“当前产出速率＋累计”开头，生产细节在下方。
- 生产关系改成竖向步骤或折行，不缩成难以辨认的一整张横向图。
- 总价值保持可见，但不压过资源主体。单位紧贴数值，长整数可明确缩写为万／亿，并在详情显示完整值。
- 320px、200% 字号不要求三条链路同时塞进首屏；保留自然滚动，不能裁掉说明和控制。

## 4. 资源映射与防止重复计价

所有资源使用共享生产视图，不从前端结果或历史列表再次求和。

| 链路 | 来源与流向 | 主展示 | 明细必须保留 |
| --- | --- | --- | --- |
| 龙门币 | `gold_produced` → `gold_consumed` → `lmd_received` | `lmd_net` 累计与每分钟值 | 龙门币收款 `lmd_received`、生产支出 `lmd_spent`、赤金生产和消耗 |
| 作战经验 | 制造站作战记录 → 经验 | `experience_points` 累计与每分钟值 | 说明单位是经验点，不是记录张数 |
| 合成玉 | `shards_produced` → `shards_consumed` → `orundum` | `orundum` 累计与每分钟值 | 当前生产、消耗和供给限制 |
| 总价值 | 共享 `sanity` | 与价值时钟一致的累计净等效理智 | 其他已计入收益的说明链接 |

- 连线表达工艺关系，不表示所有节点共享相同数值，也不宣称赤金生产与消耗在当前时刻完全相等。
- 如果赤金消耗大于产出，显示“部分消耗来自已有库存”；净变化在明细中保留符号。若没有库存来源证据，不能画出额外资源流。
- 合成玉链路使用现有供应约束后的账本，不按未约束的理论订单数展示超额产出。
- `lmd_net` 为负时如实显示生产支出大于贸易收款；不要把负值动画成“负向生产”。收款线仍显示实际估算收款，净额由文本说明。
- 总价值沿用原净估值；不把赤金、碎片、贸易所得再分别估价后相加，也不遗漏回收站、会客室和办公室已经计入的价值。
- 三个主资源覆盖部分产出，不能标成“总价值的完整分项”。

## 5. 动效必须跟随什么

### 数字

累计值和当前速率由共用时间快照派生。读数更新不驱动整条链路重新挂载；改变主题、窗口大小、全屏或打开明细不清零。

数值按共享规则更新与舍入，不为视觉热闹将 1 个资源画成实际增长的 10 个。

### 连线与流动标记

- 节点存在有效正产出时，相应连线可以显示轻微移动标记；没有速率时保持静止，保留节点和零值。
- 流动速度只表达相对快慢，采用有上下限的视觉映射，避免大样本时疯狂闪动。它不标注为订单速度，也不反推出账号数。
- 跨资源单位不能用同一个标记表示等量：1 个经验点和 1 个合成玉不等价。主读数始终提供各自单位。
- 网络失效、快照到期、数据重建、手动暂停、减少动态效果或页面隐藏时停止装饰运动。

### 平均产出进度

小站点或低速合成玉可能很久不改变整数读数，需要一个有数值依据的进度，而非随机脉冲。

1. 每条链路选一个明确的“展示批次”，例如“一批 1 个合成玉”；批次数量从固定的 1／10／100 等档位中选择，使进度在实际速率下可读。
2. 批次单位始终显示，例如“平均每批 10 个合成玉”。这只是展示单位，不能写成真实订单或新增累计奖励。
3. 进度相位由同一系列的累计资源值对批次取余计算，不从组件挂载时间起随机倒数。一次只保留一条进度，不累计排队播放错过的动画。
4. 若预计等候很长，显示真实的“预计下一展示批次还需……”；没有正速率时显示“当前暂无产出”，不无限跑进度。
5. 数值校正或批次档位变化后重置到新快照对应相位，保持主数可读，不回放历史完成事件。
6. 共享总量是连续平均数，进度满格只表示跨过展示阈值，不声称某游戏账号刚刚完成生产。

首版使用固定资源累计口径，不增加“动画倍速”“资源加速”等容易混淆产出真实性的控制。测试工具可以改时钟与夹具，产品界面不提供假速率。

## 6. 交互与资源明细

- 点击链路标题或“查看资源明细”展开对应区域，显示累计、每分钟值、收款／支出及必要的供给说明；键盘 Enter/Space 可用。
- 不把全部信息藏在 hover 提示中。图标提供明确文本标签，连接线和流动标记作为装饰从无障碍树隐藏。
- “暂停动态显示”冻结数字及装饰画面，展示暂停状态；服务端累计继续。点击继续后重新读取并回到当前值，不从暂停位置慢慢补演。
- 全屏由用户主动打开，沿用共享回退与退出行为，保留主数、暂停按钮、数据状态和口径。
- “查看总价值”跳转价值时钟；“看看排班多赚了多少”跳转增益页；“从此刻观察”进入围观窗口。三个链接都是真实导航。
- 本站保存的排班自动计入，页面直接展示共享账本。

## 7. API 与前端实现边界

本页直接消费 `GET /api/site/value-clock?view=production`，不新增工厂专用统计接口，不从公开接口拉账号列表。快照同时提供三条链路的资源向量与总价值，确保同一锚点一致。

查询复用 `['public', 'value-clock', 'production', null, null]`，与价值时钟共享请求和缓存；离开本页暂停装饰与轮询订阅，不额外在隐藏工厂中保留循环。若工作台保留了页面 DOM，必须显式传入可见状态并遵循同样清理。

前端增加的是资源链路布局和可复用的轻量进度展示；数值校验、单位换算、有效时间限制和归一化不在动画组件里实现。优先复用共享时钟、现有资源图标、主题和展开组件；只有跨链路重复且有明确职责时才提取组件。

动画计时不依赖 `setInterval` 累加“每次加一个资源”，也不因掉帧改变累计。后台页停止请求与绘制，回前台先取有效快照。遵循[查询规范](frontend-queries.md)和共享文档中的校准、版本更新与失败处理。

## 8. 全部数据状态

| 状态 | 链路与数字 |
| --- | --- |
| 首次加载 | 链路骨架静止，累计未读出前为占位 |
| 没有活动账号 | 保留已有累计，所有当前速率为 0，停止流动 |
| 某资源无产出 | 该链路显示 0 与静止状态，其他链路照常 |
| 某项未知 | 该项显示“暂不可用”，不补 0 或继续上次速率 |
| 存在库存支撑 | 显示库存补充的文本状态，按已知截止时间停止外推 |
| 当前净收入为负 | 保留带符号净额，收款和支出分开解释 |
| 刷新失败但快照有效 | 保留数据与轻量更新提示，仍受有效期限制 |
| 快照到期／断网超时 | 冻结全部数字、进度和流动，显示最近有效时间与重试 |
| 历史修订／更换统计口径 | 重新锚定数据和进度，不回放虚构产出 |
| 功能未开放 | 标准未开放状态，无后台请求和动画 |

## 9. 可访问性与性能验收要求

- 每条链路有标题、当前速率、累计与单位的文本表达。即使移除动画和连线，页面仍可完整理解。
- 读屏不逐资源增长播报；使用共享低频状态提示，资源明细可主动读取。
- 减少动态效果时直接显示数字与静态生产关系，移除流动、位移、发光和进度绘制动画；保留暂停显示能力。
- 当前主题的文本和控件对比度遵循现有规范。不能用亮度很低的连线作为唯一信息来源。
- 不使用无限增长的 DOM 标记或事件日志；装饰标记数量固定，页面停留 30 分钟后节点数稳定。
- 选用轻量 SVG/DOM 动效，只有在性能证据显示必要时才采用其他渲染方案；不要求引入新图形依赖。
- 页面隐藏时无装饰绘制和周期请求；卸载后无残留计时器、监听器或全屏状态。

## 10. 实施与验收清单

### 开发顺序

1. 接入共享生产快照，用静态链路验证数值与单位。
2. 做桌面、手机与全屏布局，完成资源详情和真实导航。
3. 增加从数值派生的进度和轻量流动，接入可见性、暂停及减少动态效果。
4. 完成数据状态与性能检查后，和价值时钟做同锚点对账。

### 数值与真实流程

- 固定快照下，工厂总价值与价值时钟精确一致，三条资源累计使用同一锚点。
- 作战记录正确换成经验点；赤金生产与消耗未重复计入总价值。
- 贸易碎片供应不足时，合成玉链路与原估值账本一致。
- 一个资源为 0、不足每秒一个整数、当前净龙门币为负、所有账号到期时均可正确显示。
- 不同刷新率、掉帧、全屏切换和暂停恢复不改变累计数值。
- 跨越展示批次时仅表现一次阈值变化；离开回来不播放错过的历史产出。
- 断网超过有效期后数字与装饰同时停止，重试成功后使用当前快照。

### 视觉与工程交付

真实浏览器覆盖 320、375、414、768、1280、1920px；手机纵向链路、桌面三条链路、明暗主题、200% 字号、减少动态效果、键盘展开和全屏退出均需实测并查看截图。至少观察一次低产出进度与一次快照校正，不以高流量夹具替代全部验收。

按[验证规范](agent-validation.md)执行相关数值派生与生命周期测试、前端构建、公开路由和文案检查、两项强制门禁。动画组件只为真实派生边界和清理行为保留必要测试，不给每个装饰节点编写镜像测试。

交付证据应包含同锚点对账、关键状态截图以及后台停止请求／绘制的实际观察；页面动起来本身不算数据正确性的证据。
