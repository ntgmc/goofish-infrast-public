# 基建技能评级

V2 的“实用工具 → 基建技能评级”公开展示干员用途和联动组合：
`/v2?section=building-ratings`。干员技能详情可以按名字跳转，链接保留当前
`profile_id`。浏览公开数据无需登录或先生成排班。

## 评价口径

评价单位是“干员、设施用途、生效阶段”。同一阶段共同生效的独立技能合并
评价；强化前的技能保留在详情，主榜显示完整形态与最低练度。无需指定搭档
即可生效的部分可以独立展示；明确联动的部分进入组合，相关入口互相连接。

固定分档为 SSS 95–100、S 85–94、A 70–84、B 50–69、C 30–49、D 0–29。
分数是人工依据机制评定的同用途参照，不是产出百分比，也不按人数分配等级。
单人和组合分榜，头像网格按设施分组、按分数降序排列，用途保留在头像下方，
可进一步筛选。同分须结合用途比较，跨设施相同分数不表示资源收益相等。
每个阶段各自给分；档案改变可用性提示与默认预览阶段。养成费用与拥有情况不参与强度分。

头像右上斜带以水平 SVG 艺术字显示等级，右下角显示分数；六档使用金、绯红、
紫、蓝、青绿、灰银区分，高等级增加切面和高光，等级文字同时保留可访问名称。
配色统一由 `tokens.css` 的 `--color-rating-*` 提供。选择头像通过共享元素转场打开详情，
查看技能、理由与解锁阶段。多变体组合默认打开符合当前筛选的变体，通过
“组合变体”切换成员与条件。红云、泡泡仓库组以固定核心展示，详情按生产配方
选择最多两名搭档及各自练度，可查看二级站两人方案；候选覆盖所有兼容的仓库
提供者及莱茵、酒神等直接联动搭档。搭档选项按当前配方和另一搭档计算组合
等级、分数及生产力，并按评分排序；必须联动换人的选项注明“需换另一搭档”，
选中后同步替换，预览与实际方案一致。干员详情仅提供该成员可用的配方。
单变体组合直接展示详情，省略变体数量、标题与选择器。关闭后返回原头像，保留筛选和浏览位置。筛选更新 URL 时保留焦点与
滚动位置，可连续输入搜索。减少动画偏好直接显示内容。评级说明和来源由
标签栏旁的“评级说明”打开。

日常基准是常规龙门币与经验生产、8 小时换班、正常休息与无人机使用，检查
243 和 252 的设施差异。源石碎片、定向加工、分阶段专精和长班在各自条件下
评价；描述中的最大值不作为整班平均。每个项目保存理由与条件，隐藏概率、
特殊叠加或缺少同版本整班实测的项目标为“暂定”。本版没有运行游戏内产出
实测，不能把机制判断写成实测收益。

能在正常轮休下完成一班的额外自身心情消耗，只小幅影响续航便利，不将工作中
的高效率折成低档。见行者和有队友时的克莱门莎均按35%搜集加速评为S；
制造站与人力办公室的同类自身消耗采用相同口径。影响其他成员的消耗、减仓、
生产力覆盖及空置工作位的代价仍分别检查。

加工站先比较副产品收益与输入配方覆盖，再评价恢复、分批加工等操作成本。
年覆盖全部精英材料配方，100%副产品加成评为SSS／95，额外2心情主要影响
批量操作便利；号角仅在炽合金块这一配方获得100%加成，减耗不能抵消覆盖
限制，日常评级为A／80。装置、聚酸酯、异铁、源岩等定向系列、单配方和
限定原始心情档位的效果采用相同口径；数值高峰不直接作为通用分数。
仅固定副产品种类的效果仍可覆盖多种输入配方，按其实际覆盖与材料需求评价。

独处技能按整间设施评价。另一成员可处于涣散状态，保留星级与精英阶段的
被动加成；机会成本是失去其正常工作的5%进驻加成与技能速度。50%独处加速
配合涣散搭档时可以达到或超过普通双人方案，心情成本按完整一班与轮休评价。
35%独处加速一般少一些整站速度；霍尔海雅、奥达还提供指定派系的下一条必得，
需连续消耗超过16点心情。每小时净消耗2点时，8小时恰为16点，尚未超过门槛；
不能将它写成8小时必定触发。制造站自动化、巫恋覆盖队友速度等效果按组合整体评价。

组合只收录明确机制联动，不穷举普通补位。仓库组按已复核搭档池展开成员组合，
赤金、作战记录分别计算；同一干员不重复占位。石棉、钼铅按同时生效技能的净
容量计算，泡泡的16格阈值分别检查每名干员；负容量保留对仓库的影响，转换收益
最低为零。稀音、刻俄柏按新进驻后8小时平均生产力计算。条件型搭档保留
心情、宿舍、外部资源与跨设施成员要求，不能当作无条件满额收益。

不同核心搭配分别成组，不能只按
设施或用途合并；同一核心的换人配套与强化前后阶段可以作为变体。指定搭档
线索、机器人充能、定向恢复、派系训练和彩虹攻防训练均按实际搭配分别展示。
变体分别给分，包内显示最低至最高
分数范围，等级显示最高变体的等级，按最高分排序。组合头像避开右上角的等级
丝带，三人组合排成左上、左下、右下；组合的分数与暂定标记放在头像下方的
独立信息带中。筛选等级、成员拥有和使用条件时，须在同一个
变体中同时成立。巫恋大单包包含巫恋、龙舌兰和柏喙／卡夫卡／折光／明椒四个
完整裁缝变体，以及嘉辛塔、渡桥、贝娜过渡变体和四个初始裁缝／初始龙舌兰变体；
明椒中枢用途另行评价。

仓库转换与自动化组合分别评价。冬时、温蒂、森蚺和异客的自动化会清除红云、
泡泡的仓库转换生产力，不能将两者叠加。冬时两个阶段均按每名同站干员增加
5 格仓库，精一另有按同站人数提供的生产力；温蒂、清流、冬时的数量型加成
可以共存。温蒂、清流、森蚺同站方案中，森蚺在制造站；中枢森蚺与 Lancet-2
支援属于另一种安排，不在同一变体中重复使用森蚺。三类温蒂组合覆盖相关核心
的强化前后阶段；两／三发电站方案按实际数量匹配，变体选择显示练度和发电站
数量。打开详情优先选择符合当前档案和设施的方案。

水月的标准化组按实际技能类别计数，普通生产力技能不能作为标准化技能。
怒潮凛冬与烈夏方案包含贸易站古米，按满足烈夏技能依赖后的75%经验生产力评价。

可露希尔的特别订单按 2 赤金换取 1200 龙门币评价，额外价值随订单加速放大；
评级仍保留同版本整班实测待复核标记。

## 会客室速度、线索倾向与组合

依据[PRTS会客室机制](https://prts.wiki/w/罗德岛基建/会客室#线索搜集速度)，
每份线索的基础生成时间为20小时。会客室等级、宿舍氛围、每名成员的星级、
精英阶段、正常工作与技能加成相加；改变线索类型的倾向不增加线索总产量。

| 成员属性 | 速度加成 |
| --- | --- |
| 1–3星 | 0% |
| 4星 | 2% |
| 5星 | 4% |
| 6星 | 5% |
| 初始／精一／精二 | 0%／8%／16% |
| 正常工作 | 5% |

星级与精英阶段加成在涣散时仍保留，正常工作5%及技能速度需成员工作。
此点也经[一图流公开实现](https://github.com/Arknights-yituliu/frontend-v2-plus/blob/275fbbb6424683493adb2bfca5043d6eba29b178/src/utils/mower/theoretical-output/engine/engine/supportFacilities/receptionClues.ts)
交叉核对。以另一位涣散六星精二保留21%为参照，五星精二50%独处技能贡献
`25 + 50 + 21 = 96%`，两名正常六星精二20%成员合计`46 × 2 = 92%`。
这里比较加成，实际搜集速度还要加设施和氛围的共同部分。

同为20%技能，12F初始贡献25%，白雪初始／精一／精二贡献27%／35%／43%。
会客室因此补齐精英化本身的强化阶段，即使技能未变化也保留阶段对比；一、二星
只保留初始阶段。综合分数在`meetingStageScores`逐人逐阶段人工维护，并考虑
速度、线索用途、条件与岗位机会成本，不由雷达图加权生成。

信仰搅拌机与菲亚梅塔宿舍支援构成联动，精二技能20%加支援10%，再加六星
精二正常进驻26%，本人合计56%。罗德岛隐秘队与焰狐龙梓兰中枢构成联动，
确定的额外速度为10%。两组均只占一个会客室工作位，另一位可以自由安排。

“更容易获得线索板上尚未拥有的线索”按线索板缺口识别，不代表仓库去重或
必得。[晓歌的技能原文](https://prts.wiki/w/晓歌)与冻结游戏数据没有给出
具体命中率或同类叠加算法；本轮可访问的公开资料与实现也未找到可靠数值。
因此同类倾向的叠加状态保留为待核实，不将两份效果算成双倍或相乘；对应图轴
留空为“待量化”，已知的速度部分仍正常相加。线索板全空或全满时没有可区分
的补缺目标；同样不能由此推导缺一条时的命中概率。

会客室的“线索定向”维度区分无定向、偏向已拥有、缺口倾向、派系倾向及
触发后的固定必得。概率未查证的倾向不填数字；“100%”仅用于满足原文条件后
的下一条固定派系线索，不代表整班或任意缺口的命中率。

## 五档分项与强化对比

后台“功能开关 → 公开工具 → 基建评级雷达图”控制公开单人详情、干员用途评级与
当前组合详情的多维评价、雷达图及分项明细。开关默认关闭，旧配置缺少该字段时
也保持关闭；开启并保存后展示。原有综合等级、分数、技能与强化阶段照常可用。

开启后展示独立的五档分项和雷达图。分项仅解释技能特点，不参与现有综合得分、等级、筛选与排序。普通效果使用
1–5档，越高越有利；订单增值等特殊收益可超档至6–9档。实际百分比、心情
增减及条件与数值表一同收在默认折叠的“分项明细”中。不能可靠换算的效果
显示“待量化”，图上留空，不按零或最低档连接。

同一干员、同一设施的强化阶段全部叠加。颜色与实线／虚线同时区分阶段，
数值表提供相同信息。干员管理当前选择的阶段以实线强调；切换组合成员、
配方或设施方案时，图表跟随当前变体更新，不把不同搭档方案当作精英化阶段
叠加。标准五圈标出1–5档，超档点延伸至第五圈外并直接标值；同一张图内
所有阶段共用尺度。

| 设施 | 主要分项 | 站点差异 |
| --- | --- | --- |
| 制造／贸易／发电／办公室／回收 | 效率／收益、通用性、心情友好、设施独立、搭配独立 | 加速采用各自技能单位；已知制造组合按工作位平均生产力 |
| 加工站 | 副产加成、高效覆盖、心情友好、设施独立、搭配独立 | 覆盖指高副产效果适用的输入配方；消耗按每次加工 |
| 训练室 | 训练加速、职业范围、心情友好、设施独立、条件宽松 | 职业范围按八职业计数，阶段／分支／连续训练另列条件 |
| 宿舍 | 恢复强度、恢复范围、心情友好、设施独立、搭配独立 | 强度为最高单人恢复加成，作用人数以五人宿舍为参照 |
| 会客室 | 线索加速、线索定向、心情友好、设施独立、岗位利用 | 速度包含进驻、星级与精英阶段；独处允许涣散搭档保留被动加成 |
| 控制中枢 | 全局支援、通用性、心情友好、设施独立、搭配独立 | 多种支援尚未折成单一强度时留空 |

分项基于当前冻结的技能描述和已知组合数值，规则位于
`src/lib/building-rating-factors.ts`，不读取综合评分。它们是可复核的描述尺度，
不是游戏内产出测量，也不表示跨设施经济收益相等：

- 普通加速参照上界：制造／贸易40%，会客室每位成员含进驻加成65%，发电25%，办公室50%，加工100%，
  训练100%，回收30%；宿舍最高单人额外恢复1.2心情／小时。将参照等分为五档，
  零加成为1档，普通加速超过参照时仍为5档，原始数值保留。明确的条件型加成
  须说明采用的可实现场景；未复核的人数、资源、渐进增长和保底规则保留未知。
- 人数与设施等级的倍率按原评级的常规可实现高配场景求总量，不把系数当作
  效率：空弦按4间5级宿舍计算，初始20%、精二40%；吉星按另有两名普通队友
  工作计算，初始20%、精二40%。满级会客室／训练室、两贸易站、两条实际赤金线、
  两类常规制造配方、64工程机器人、200无人机容量和三个额外招募位采用同一
  口径，并合并本阶段其他生效技能和适用的跨设施支援；例如凛御银灰支援下的
  银灰／崖心／角峰按50%基础加成加10%支援，合计60%。具体参照在折叠明细中
  逐项说明；这是评级
  场景，不代表当前档案已经满足。渐进制造沿用原评级的8小时平均，稀音21.25%、
  刻俄柏23.125%，不取更长班次的25%峰值。伊内丝采用同样8小时口径，技能平均26.25%。
  会客室组合的已知速度按工作成员平均显示，星级、精英阶段、正常工作与技能分别列出。
- 特殊订单收益独立按机制复核：但书初始阶段违约订单交付额外+1为6档，精二
  额外+2为8档；可露希尔固定2赤金交付1200龙门币兼有订单加速为9档。贸易站
  效率轴显示“订单收益”，不将这些数值误写成加速百分比。超档为单独维护的
  机制分档，不从最终综合得分反推。
- 加工高效覆盖：各类加工5档，精英材料4档，技巧概要／基建材料／芯片单类别
  3档，材料系列、两个配方或原始心情档位2档，单配方或无副产加成1档。
  只改变副产品种类的效果按实际输入范围计，不当作单输入配方。
- 心情友好：自身无额外消耗为4档。每小时增减或加工2／4／8三档原始配方的
  平均消耗变化，采用 `3.75 − 1.25 × 变化量` 向上取整并限制到1–5档。
  这是固定分档参照，不代表各类加工配方的使用频率。明细同时显示
  消耗增减范围；概率返还、动态消耗及清除规则未折成固定数值时留空。
- 设施独立按额外依赖的设施或布局条件类别计数；组合搭配独立按其余配套成员计数。
  单人明确要求指定搭档／派系时标记一类依赖，不把它写成精确人数。
  两者用 `5 ÷ (1 + 数量)` 向上取整。训练条件宽松采用同样分档，计入阶段、
  分支、连续训练时长与搭档条件。

## 档案与练度

干员管理点击头像打开“技能与评级”，可在用途评级、全部技能和联动组合间
切换。用途评级默认选择档案真实练度已解锁的最新阶段；尚未达到的阶段可
预览并标明练度要求。基建技能的解锁要求中，一、二星只显示等级，三星及以上
只显示初始／精英化阶段，技能详情标题采用相同显示；底层解锁条件仍完整保留。
等级缺失时保留待确认，已被替换的技能仍可查看。
管理页使用实际导入练度，与排班的模拟培养等级分开。联动组合只提供包含
当前干员的变体，优先选择满足已知条件的方案，其次选择当前干员已解锁的
阶段；使用完整档案和当前设施配置检查成员、练度与条件，搜索不裁剪搭档。
组合可在详情内展开、切换，关闭详情保留干员搜索、滚动位置并恢复头像焦点。
“查看技能评级与组合”仍可跳转公开评级页，保留当前档案。

档案拥有任意一个完整变体的成员，即显示“成员已齐”。练度与设施再分别
检查；未知等级、宿舍人数、心情区间、实际训练／加工任务及待安排的工作位
保持“待确认”。成员齐全不等于已能执行该组合。页面不修改档案和排班。

当前配置可确认贸易站／制造站的等级、贸易站与发电站数量、赤金生产线数量。
配置缺少明确设施等级时保留未知，不从布局名称推定满级。未来导入更多设施
资料时，应在共享匹配逻辑中增加有来源的条件判断。

评级页展示成员与最低练度要求，不计算或展示养成费用。共享模型保留
`buildingRatingTrainingCost` 及测试，复用 `calculateTrainingCost` 估算升级经验、
升级和精英化龙门币；未知等级或未拥有时返回未知，费用不参与评分。

## 数据与维护

- `src/data/building-skills.json`：游戏技能、技能槽和解锁阶段快照。
- `src/data/building-skill-ratings.json`：固定发布的评价源数据，包含版本、日期、
  公开来源、逐技能参照、同人生效集合的合评、会客室逐人各精英阶段评分、组合变体、稀有度及复核指纹。
- `src/data/building-rating-warehouse-partners.json`：仓库搭档各生效阶段的净容量、
  配方生产力和外部条件；与技能快照一起复核。
- `src/lib/building-rating-warehouse.ts`：展开二人／三人仓库搭配，计算净容量、
  逐人转换、配方与莱茵等联动；按每个工作位的生产贡献参照给分，并扣除跨设施
  配套位置成本。该参照属于仓库组内机制评级，不是游戏内整班实测。
- `src/lib/building-skill-ratings.ts`：按技能槽组合生效阶段、分档、查询、档案
  匹配与费用；浏览器只读取本地数据。
- `src/lib/building-rating-factors.ts`：独立五档分项与原始依据，保留未知值。
- `src/pages/v2/BuildingRatingFactors.tsx`：强化叠加雷达图与默认折叠的可访问数值表。
- `src/lib/building-skill-ratings.test.ts`：全量覆盖、复核指纹、合法成员与容量、
  共同核心与强化阶段、指定裁缝变体、档案条件和费用函数验证。

固定快照覆盖 438 名干员、778 个技能定义、10 类设施，包含 89 个固定组合
和 2 个按搭档池展开的仓库组合，保留强化前后各阶段。相同效果与条件使用同一参照；合评须说明同时生效、取最高
或有副作用的关系。稀有度来自同一游戏提交的 `character_table.json`，用于
解锁阶段显示、会客室进驻加成与费用计算。本站分数由技能机制独立判断。

同步游戏技能后，运行：

```sh
pnpm test src/lib/building-skill-ratings.test.ts
```

测试对每个技能定义和每名干员的解锁序列检查规范 JSON 的 SHA-256，检测新增、
删除、效果及解锁变化；也检查所有用途有独立或组合归属、组合成员有效、每人
只有一个位置、同站人数不超容量，且每项依赖技能都有在对应阶段真正生效的变体。失败时逐项复评，更新固定评级版本与日期，
再更新对应复核指纹。不要只改指纹让测试通过。新增或失效联动需同时调整变体、
理由和条件，保持最低练度及强化前后描述一致。

每次更新运行相关测试、`pnpm run build:web`、`pnpm run check:copy` 和仓库
必需检查，并验证公开访问、档案切换、筛选、键盘打开和关闭详情、变体切换、
焦点返回、手机和浅深色显示。
