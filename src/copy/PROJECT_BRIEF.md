# MaaTool 文案优化项目简报

本文档用于给 DeepSeek 或其他文案工具提供必要的产品上下文。优化文案前，请同时读取本文档、`README.md` 和需要修改的 `zh-CN/*.ts` 文件。

## 1. 一句话定位

MaaTool 是面向《明日方舟》玩家的 Web 工具：根据玩家当前的干员、库存和基建配置生成可执行的基建排班，解释收益与培养建议，并导出可供 MAA 使用的排班 JSON。

它不是资讯站、社区、游戏代练服务或自动登录游戏的工具。它的核心价值是把复杂的基建计算转化为用户可以检查、比较和带走的结果。

## 2. 产品目标

MaaTool 希望帮助用户完成以下任务：

1. 安全、清楚地导入自己的干员与库存数据。
2. 用尽量少的步骤确认计算所需的基建房间、产物和换班规则。
3. 根据当前账号实际情况生成排班，而不是只提供通用攻略。
4. 展示方案的预计产出、效率、等效理智、练度成本和回本依据。
5. 输出可导入 MAA 的 JSON，减少手工配置成本。
6. 比较不同布局、生产方案、换班方式和无人机策略，帮助高级用户做取舍。

产品不应承诺某个方案一定可用、一定最优或一定获得特定游戏内收益。结果会受到游戏版本、数据完整性、干员状态、订单、疲劳、实际执行方式和 MAA 配置影响。

## 3. 目标用户

### 主要用户

- 已经使用或准备使用 MAA 基建功能的《明日方舟》玩家。
- 希望根据自己的干员池生成排班，而不是照搬通用作业的玩家。
- 关心日产出、等效理智、培养成本和回本时间，希望知道“为什么推荐”的玩家。
- 希望降低配置门槛，但仍想保留对数据来源、计算条件和最终文件的控制权的玩家。

### 典型心态

- 熟悉《明日方舟》基础概念，但不一定理解优化算法。
- 对二维码、授权凭据、CDK、上传 JSON 等操作可能有安全顾虑。
- 希望快速完成任务，不想被冗长教学、营销弹窗或模糊状态打断。
- 遇到失败时需要明确知道发生了什么、数据是否已经保存、下一步该做什么。

## 4. 核心用户旅程

### 4.1 公开访问

用户可以在首页了解产品，也可以直接使用免费的仓库估值工具。公开页面还包括公告、FAQ、联系客服、隐私政策、服务协议和免责声明。

首页应优先回答：

- 这个工具能生成什么？
- 需要准备哪些数据？
- 是否需要提供游戏账号密码？
- 最终能否导出 MAA JSON？
- 结果如何帮助用户判断收益和培养方案？

### 4.2 注册与登录

用户通过邮箱和密码创建或登录 MaaTool 账号。注册时 CDK 可以为空；用户也可以先进入账号页，再添加免费档案、升级档案或兑换新的 CDK 档案。

相关文案应区分：

- MaaTool 登录密码；
- CDK；
- 森空岛二维码或授权凭据；
- 游戏账号档案。

这些概念不可混写，也不要暗示用户需要提供《明日方舟》游戏账号密码。

### 4.3 添加游戏账号档案

一个 MaaTool 用户账号可以管理游戏账号档案。档案可能来自免费体验、CDK 或仓库估值流程，具体权限和状态以工作台实际展示为准。

用户可通过以下方式准备数据：

- 使用森空岛 App 扫码授权；
- 粘贴森空岛本地授权凭据；
- 上传 MAA 导出的干员识别文件；
- 在仓库估值场景上传 MAA 仓库 JSON。

森空岛流程的重要交互事实：

1. 授权或读取后先展示昵称和 UID。
2. 用户再次确认后才保存绑定和导入数据。
3. 账号不一致、二维码过期、等待超时或凭据失效时，应告诉用户如何重新授权。
4. 不要把“已读取预览”写成“已完成绑定”或“已保存”。

### 4.4 确认工作区

用户检查干员数据和基建配置，包括房间数量、生产目标、换班方式、无人机策略及其他计算所需规则。页面会指出无法生成结果的缺项或不合法配置。

文案应帮助用户理解“为什么现在不能继续”和“修改哪一项可以继续”，不要只写“参数错误”或“操作失败”。

### 4.5 生成排班

生成过程可能经历排队、读取数据、计算排班、整理结果、完成或失败等状态。部分任务可能具有不同队列优先级，邀请奖励可能提供优先计算券。

状态文案必须：

- 区分尚未开始、排队中、运行中、完成和失败；
- 不把预计等待时间写成保证；
- 不在任务仍运行时暗示结果已经可下载；
- 失败时优先给出可执行的恢复动作。

### 4.6 查看与导出结果

结果可能包含：

- 可导入 MAA 的基建排班 JSON；
- 房间与班次安排；
- 预计效率和日产出；
- 等效理智；
- 无人机使用摘要；
- 干员练度或精英化建议；
- 培养成本、收益增量和回本参考；
- 方案依据、算法说明或风险提示。

游戏内轮换模式不一定生成 MAA JSON。不要在所有结果场景中无条件承诺可下载 JSON。

### 4.7 场景对比

高级用户可以组合比较不同基建布局、生产方案、MAA 换班方式、游戏内轮换方式和无人机策略。结果用于寻找收益和每日实际换班次数之间的取舍，并展示 Pareto 前沿。

这里的文案应准确区分：

- 快速结果与精确结果；
- 生产收益与换班操作成本；
- MAA 排班与游戏内轮换；
- 被跳过、被合并、运行失败和正常完成的场景。

## 5. 主要功能模块

| 模块 | 用户目标 | 文案重点 |
| --- | --- | --- |
| 首页与公开信息 | 判断工具是否适合自己 | 结果、数据要求、安全边界和明确入口 |
| 账号与认证 | 创建账号并安全进入工作台 | 状态清楚，避免混淆密码、CDK 和森空岛凭据 |
| 游戏账号档案 | 管理不同游戏账号的数据与权限 | 明确当前档案、状态、来源和操作影响 |
| 森空岛导入 | 授权、预览并确认导入 | 强调先预览后保存，提供失败恢复动作 |
| 工作区配置 | 补齐生成排班所需条件 | 用用户能理解的方式指出缺项与约束 |
| 排班优化 | 生成符合当前账号的方案 | 真实描述排队和计算状态，不夸大结果 |
| 结果与练度建议 | 判断方案是否值得采用 | 同时说明收益、成本、依据和不确定性 |
| 场景实验室 | 比较多个策略组合 | 帮助理解取舍，避免把估算写成确定事实 |
| 仓库估值 | 估算库存的等效理智价值 | 强调估值口径和参考性质 |
| CDK 与邀请 | 开通档案能力或获得优先计算券 | 权益以页面实际状态为准，不编造价格或期限 |

## 6. 关键术语

### 必须保持一致

- **MaaTool**：本产品名称。
- **《明日方舟》**：游戏名称，正式内容使用书名号。
- **MAA**：第三方开源自动化工具，不能写成 MaaTool 自有功能或官方合作方。
- **森空岛**：用于授权和读取用户游戏数据的第三方服务。
- **基建排班**：干员在基建房间和班次中的安排。
- **排班 JSON / MAA JSON**：可供 MAA 自定义基建配置使用的导出文件；根据语境选择更清楚的称呼。
- **等效理智**：用于把不同产出或库存价值放到同一参考口径的指标，不等于游戏实际直接发放的理智。
- **练度建议**：基于计算结果给出的培养参考，不是必须执行的指令。
- **回本**：培养成本与预期收益增量之间的参考关系，不应写成确定收益保证。
- **CDK**：用于开通相应游戏账号档案能力的兑换信息，不等同于登录密码或游戏账号。
- **游戏账号档案**：MaaTool 中用于保存某个游戏账号数据、配置、权限和历史结果的工作区对象。
- **优先计算券**：用于影响计算队列优先级的奖励；不要简称为现金券、充值券或 CDK。
- **Pareto 前沿**：场景对比中无法在一个指标变好时不牺牲另一个指标的候选方案集合。首次面向普通用户出现时应配合通俗解释。

### 容易混淆的概念

- “MaaTool 账号”不等于“《明日方舟》游戏账号”。
- “森空岛授权”不等于要求用户提供游戏密码。
- “预览账号”不等于“已经保存绑定”。
- “排班已生成”不等于“已经应用到游戏或 MAA”。
- “预计产出”不等于“实际到账产出”。
- “免费仓库估值”不等于完整排班优化权限。
- “MAA 排班”与“游戏内轮换”是不同运行方式。

## 7. 品牌语气

MaaTool 的语气应当是：专业、克制、直接、透明、可信赖。

### 应该这样写

- 先说用户能完成什么，再解释技术细节。
- 使用短句和明确动词，例如“上传”“确认”“生成”“下载”“重新授权”。
- 状态信息说明当前发生的事情；错误信息说明原因或可执行的下一步。
- 涉及数据、安全和付费权益时，写清触发条件、保存时机和影响范围。
- 用“预计”“测算”“参考”“可能”等词准确表达不确定性。
- 保留游戏和 MAA 用户熟悉的术语，但在首次出现的复杂概念旁补充解释。

### 避免这样写

- 不使用“全网第一”“绝对最优”“稳赚”“百分之百准确”等夸张承诺。
- 不制造焦虑、稀缺感或强迫连续使用，不使用签到、错失恐惧或游戏化留存话术。
- 不把技术实现细节直接丢给普通用户，例如只显示内部错误码、字段名或算法类名。
- 不用空洞按钮，如“好的”“提交”，如果可以写成更具体的“确认绑定”“生成排班”“下载 JSON”。
- 不用责备用户的语气。失败时描述条件和恢复方式，不写“你操作错误”。
- 不擅自改变法律文本的事实含义、责任边界或数据处理范围。

## 8. 安全、隐私与第三方边界

优化以下内容时必须保持事实准确：

- MaaTool 不要求用户提供《明日方舟》游戏账号密码。
- MaaTool 登录密码不会以明文保存。
- 森空岛绑定可能涉及二维码或授权凭据；用户不应在 QQ 群或公开渠道发送这些内容。
- 森空岛授权读取后先展示账号预览，用户确认后才保存绑定和导入数据。
- 服务会根据功能需要处理邮箱、会话、游戏 UID、昵称、干员、库存、基建配置、排班结果和必要授权状态。
- 用于持续导入的森空岛凭据会在服务端加密保存。
- MaaTool 不出售用户个人信息，也不将游戏数据用于与服务无关的广告投放。
- 账号删除、更正或数据咨询通过 MaaTool QQ 群联系官方，并可能需要身份核验。
- MaaTool 是独立工具，不代表、未获授权代表，也不与鹰角网络、森空岛或 MAA 项目建立官方隶属关系。
- 《明日方舟》、森空岛、MAA 及相关素材和名称的权利归各自权利人所有。

若准备改写隐私政策、服务协议或免责声明，应逐段保持事实和法律含义，不要为了“更有吸引力”而弱化限制、扩大承诺或新增未实现的数据用途。

## 9. 不可杜撰或擅自修改的内容

除非开发者另外提供已确认事实，否则文案工具不得：

- 编造价格、折扣、销售期限、退款规则或购买平台。
- 编造 CDK 等级对应的具体功能、额度、有效期或更新次数。
- 编造计算速度、准确率、节省比例、用户数量或成功案例。
- 宣称 MaaTool、鹰角网络、森空岛或 MAA 之间存在官方合作、授权或隶属关系。
- 宣称所有模式都能导出 MAA JSON。
- 宣称结果一定最优、一定提高收益或与游戏实际完全一致。
- 改变数据收集、存储、删除、安全措施或第三方传输的事实。
- 新增当前产品不存在的入口、按钮、功能或客服渠道。
- 修改对象 key、函数参数、稳定 id、路由、枚举、资源路径或 API 错误码。

遇到信息不足时，保留原意并列出待确认问题，不要自行补全商业事实。

## 10. 文案文件结构

文案位于 `src/copy/zh-CN/`：

- `common.ts`：跨页面通用内容和购买渠道显示文案。
- `public.ts`：首页、公告、FAQ、支持、法律内容和公共页脚。
- `auth.ts`：登录、注册、密码重置和账号删除撤销。
- `dashboard.ts`：档案、工具入口、兑换、邀请、公告和设置。
- `workspace.ts`：森空岛导入、数据准备、工作区和本地文件。
- `optimize.ts`：生成流程、配置、结果、练度建议和场景对比。
- `tools.ts`：仓库估值。
- `metadata.ts`：页面标题、SEO 描述和社交分享元数据。
- `domain.ts`：房间、产品、无人机策略及前端业务校验文案。

当前 key 主要用于保持代码引用稳定，不一定能单独表达完整语境。修改某条文案前，应根据它上方的来源文件注释搜索对应的 `copy.<domain>.<key>` 引用，阅读相邻界面和前后状态。不要只根据 key 猜测含义。

部分字符串包含换行、前导空白或句子片段，用于保持 JSX 布局或拼接动态值。除非同时检查调用处，否则不要删除空白、标点或改成无法拼接的完整句子。

## 11. 优化优先级

建议分批处理，不要一次重写全部 catalog：

1. 首页、SEO 元数据和公开工具入口：提升定位清晰度和首次理解速度。
2. 注册、档案创建和森空岛导入：降低安全顾虑和操作歧义。
3. 工作区配置、生成状态和错误恢复：提高任务完成率。
4. 结果、练度建议和场景对比：让指标、依据和取舍更容易理解。
5. FAQ、支持页和公告：减少重复咨询。
6. 法律文本：只做可读性优化，并进行人工事实与法律复核。

每批应单独输出修改说明和风险点，便于审查与回退。

## 12. 单条文案自检

提交修改前检查：

- 用户能否立刻知道当前状态？
- 用户能否知道下一步动作？
- 是否准确区分账号、档案、CDK、密码和森空岛凭据？
- 是否把估算、预计或建议写成了确定结果？
- 是否暗示了尚未发生的保存、绑定、导入、应用或下载？
- 是否保留动态值前后的必要空格和标点？
- 按钮是否描述了真实动作及影响？
- 错误提示是否提供了恢复方向？
- 是否引入了未经确认的功能、权益、价格或安全承诺？
- 是否保持对象 key、参数、稳定 id 和 TypeScript 语法不变？
